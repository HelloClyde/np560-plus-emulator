## 依据与修复前反例

按 PDF 技能完整目视核对 [CN1916884A](../../tmp/cnpatent/CN1916884A.pdf)
PDF 第 16–17 页（说明书第 13–14 页）：第二阶段译码、间接地址计算、读取操作数，
并可进行间接寄存器 post increment / pre decrement；第三阶段计算，第四阶段写回。
据此让本条指令的后增地址在结果写回前确定，不让结果改变本条指令已使用的寻址配置。
这不是新增完整周期流水线模型，也不能解决资料未写清的全部寄存器写冲突。

原核心 SHA-256：`40f88f23ecd1dd75fbb4335780bfc94d56b8ac1a84b23a1b269002825ed9f975`。
诊断 guest 设置 `XM0=0`、`X0=F126`、`R0=1`，执行原始编码 `1A80`
（`MOV [R8++],R0`）。`F126` 是目前 XM0 的数据总线别名。

- 写入结果为 `XM0=1`，这是应保留的本条存储副作用。
- 旧实现随后重新读 XM0，以长度 1 的环计算本条地址，得到 `X0=F126`。
- 按进入指令时的线性配置，应得到 `X0=F128`；新 XM0 应影响后续指令，而不是追溯影响本条。

旧核心现场：[word-store-linear-icountNone.json](../../tmp/np560-agu-writeback-before-20260906-v1/word-store-linear-icountNone.json)。
反例确实失败，guest 无宿主 RAM 写入、无 NAND；QEMU 正常退出，不是进程崩溃。
该次总报告因首个断言中止而 `cases=[]`，实际寄存器证据保存在上述单项 JSON。

## 实现变化

`qemu-dmcu/target/dmcu/helper.c`：

- MOV 后增写入、后增读取、单侧与双侧后增搬运，先计算下一地址，再执行数据/寄存器写回。
- 内存移位在写回结果前保留下一地址；间接 ALU 和指数读取同样提前取得后增地址。
- 双指针搬运同时保留原始源/目的地址，不在数据写入副作用后重新读取它们。
- 仍使用现有 `pointer_postincrement` 的线性和环形规则，不按原厂 PC、应用或游戏名特判。
- 与此前 [内存 MAC](np560_memory_mac.md) 的预先计算方式一致；本轮没有改变 MAC 算术、
  modifier 地址映射、ROM、PRG、NAND、键盘或 Web 显示实现。

双侧后增若使用同一个指针，现有“双更新”行为保留，硬件冲突语义仍未确认。
目的 GPR 与指针自身重叠的写优先级也没有由本轮测试全面确认；不能借此宣布全部别名正确。
XC/YC、其余 modifier 映射、可变步长与位反转仍未实现，不能从流水线说明中推导它们的地址。
