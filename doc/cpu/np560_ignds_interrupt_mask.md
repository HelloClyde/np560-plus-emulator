# IGNDS：硬件中断提前进入导致错误银行写入

日期：2026-09-05。已修复 CPU 的确定错误；不是历史菜单/资源损坏的完整根因结论。

## 原厂指令约束

已目视核对原始 `tmp/cnpatent/CN1916884A.pdf` 的 PDF 第 114 页（说明书 111/123），
IGNDS 条目不仅要求后续指定指令忽略 DS0/DS1 地址计算，还明确要求这段指令期间
不允许硬件中断。相邻 PDF 第 113 页是 CRIT，不能因为已有 CRIT 屏蔽就省略 IGNDS 屏蔽。

本次保留现有两字节编码 `3F10..3F13` 及编码低两位加一得到 1–4 条指令的实现。
这些页没有明确解释立即数到条数的加一编码，本次没有新增该部分的真机证据。
定向程序检验现有条数约定下的中断边界，不把自测通过说成完整编码已获硬件验证。

## 修复前的可重复错误

诊断 guest 自己设置 DS0=44，初始化内部逻辑地址 `2600=1111`、对应银行地址
`22:2600=EEEE`，令 R0=1234。它先产生待处理 ICR 请求，再用 CRIT 覆盖设置请求和
IGNDS 本身。CRIT 结束时只有 IGNDS 继续生效，下一条是 `MOV [2600],R0`。

旧核心在这个边界允许硬件 IRQ 进入；向量跳转消耗了前台的 IGNDS 条数。
RETI 返回后，原本必须写内部 RAM 的 MOV 恢复了 DS 银行计算，写坏了外部标记。

同一个单条保护反例的前后结果：

| 观察项 | 修复前 | 修复后 |
| --- | --- | --- |
| IRQ 保存的前台 PC | `20:0452`，受保护 MOV 尚未执行 | `20:0456`，MOV 已完成 |
| 内部地址 `00:2600` | `1111`，目标未写入 | `1234`，正确写入 |
| 银行地址 `22:2600` | `1234`，原标记被破坏 | `EEEE`，保持不变 |
| 返回 SP | `4000` | `4000` |
| IRQ 进入/返回及 BAD | 1/1、BAD=0 | 1/1、BAD=0 |

这说明“没有非法指令、返回地址错误或 BAD 诊断”不足以判断寻址正确。
它不是模拟未实现指令，也不是宿主改 RAM 制造的返回错误；所有设置和写入来自 guest 指令。

旧二进制反例保存在 `tmp/np560-ignds-irq-before-v2/`，SHA-256 为
`4a96b19b1dd6fc83c2a29f0c7b7475a097d4c7a6c6721dfe399c181eb5241081`。
`before-v1` 缺少诊断 resident 配置，先撞到原有 ROM 空洞保护；不把它作为错银行证据。

## CPU 修正及边界

`qemu-dmcu/target/dmcu/cpu.c` 的硬件中断准入条件加入 `env->ignore_ds_count`。
保护期间保留待处理 ICR.RQ 和 CPU HARD 请求，最后一条受保护指令完成后才准许进入。
不清掉请求，不改写 SOCR.IE，也不在保护结束时擅自打开原本关闭的全局中断。

现有 `helper.c` 在 IGNDS 状态变化时结束翻译块并刷新相应地址翻译，使准入检查发生在
正确的指令边界。寻址与条数递减实现未改；没有按调用者、菜单或资源地址特判。

本次只修 CPU 硬件 IRQ 的准入：

- DTU 仍在 CPU 准入检查之前运行；不能据此声称已实现 CRIT/IGNDS 对总线传输的原子性。
- 同步 TRAP、EXR 异常在 CRIT/IGNDS 内的行为尚未验证。
- 未改变寄存器保存约定、ROM 算法、文件分配或原厂资源内容。
- 尚未取得历史 `22:1840` 损坏的第一写入者，不能把该历史故障直接归因于这次修复。
