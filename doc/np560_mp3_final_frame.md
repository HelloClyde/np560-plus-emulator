# MP3 HLE v5：实际 EOF 下的有界末帧

更新：2026-09-08。此实现是用户允许的 ROM 01/02 行为兼容 HLE，**不是取得原厂 ROM**。

## 根因与边界

原厂 `16:EC34 → EC6C/ED0C → 1C:CCD4` 按字节读取文件，`31:EB24` 保持真实返回长度，
仅在配置要求时做逐字节 XOR。`16:ECFA/ECFC`、`16:ED9A/ED9C` 把实际字节数右移一位，
保存为 word 数；`16:EA42 → E844` 随后只把这些完整 word 发布到压缩输入环。

测试文件 `tone440.mp3` 共 48483 字节、116 帧。旧快照的第二源缓冲从文件偏移 45056
开始，3427 字节逐字节匹配，最后的 `AA` 确实读到了 RAM；但发布数 `06B1` 只涵盖 3426
字节。环内最后一帧因此只有 417/418 字节，v4 在调用解码器之前就将其判为输入不足。
文件读取未少读；缺失 ROM 的 word 环接口没有已证实的额外尾字节参数。

最后一帧的 `main_data_begin=465`，四个 `part2_3_length` 为 `[1958,0,730,0]`，共 2688 位。
必需音频位已在实际 reservoir 中，缺的末字节不承载该帧音频位。
FFmpeg 对完整文件和截去最后一字节的文件，采用同样的 bitexact/skip_manual 配置，
均输出 534528 字节、逐字节相同的 PCM：
`f55f254eb00154ea619fb30e39b1bda99386b718b3bfe2685f0a43616ca24883`。
这证明该文件可有界恢复，不证明任意残缺 MP3 都可以播放。

## 实现

- 构建器显式 `--final-frame` 生成 v5；v1–v4 和普通完整帧解码契约保留。
- 环仅在声明帧长不小于实际剩余输入、且原厂生产者已发布 `BIT89.7` 时申请 final。
  完整且正好耗尽输入的末帧也属于 final；普通完整帧和临时短读不属于 final。
  工作区 `0x66` 为重建实现的标记，`LENGTH`、消费量和回收游标都使用实际字节数。
- HLE gate 独立检查原厂 EOF 位，不信任工作区标记；不会设置 EOF、ready、EN 或偷读源缓冲。
- `np560_mp3_codec_decode_final()` 要求完整 header/CRC/sideinfo、实际 reservoir 和全部声明音频位。
  使用同一 minimp3 Layer III 内核，不修改上游头文件、不补造压缩字节；内部有界读的防护空间
  不算作输入或 reservoir。失败不提交候选状态，也不产生 PCM。
- MPEG-1 的两颗 granule 仍分别交付；末帧保留真实输入占有直到下一次 step，才发布
  `3350/3352` 消费量并回收。重复查询既不会回收，也不会凭空扩大或缩小实际容量。
  DTU/DAC 与原厂播放器继续执行，未把宿主文件播放器接到 Web。

## 第一轮整机发现：最后一颗 PCM 仍被提前结束

`tmp/np560-mp3-final-player-20260908-v1/report.json`：退出 0，12 次观察累计 228 帧、455 颗，
所有解码/空间/复制错误为 0，final 成功调用 1 次，旧会话 release 为完整 116 帧/232 颗。
但这只解决了解码量，未解决最后 PCM 的交付。

录音 362332 帧、7.548583 秒，左右完全相等、无采集缺口；PCM SHA256：
`473e4743fb95b4d3ede0126a7f9cb0c03247134b71dae8b2176adc652a4eb095`。
首轮源 `[1152,133056)` 的 130310 个变化值全段相等，对应 131904 次 DTU 写入/路、229 颗。
frame 115 第一颗已进入 WAV `217047..217673`，但其第二颗完全没有输出：源 `133055=-28`
后本应是 `133056=-62`，实际变成原厂退坡 `-23,-19,-14,-10,-5,-1,0`。
第二颗的六段独立签名均不存在；它有 422 个非零样本、峰值 551，不能视作静音 padding。
该轮差额是**启动 2 颗＋结尾 1 颗**，而非仍然少解码一帧。

关闭到重开为 93.321167 ms，关闭到 release 入口为 87.962292 ms；约 143 ms 交接静音仍在。
这是部分时序模型与暂停诊断内的结果，不是用户 Web 实时验收。

## 第二轮修正：最后输入占有延续到下一次 step

`16:E8A8/E8B0` 先保存旧消费量；`E906..E91C` 用本次消费增量与 `766-free_words` 比较。
末帧交付后立即结算全部输入，会使两者相等，`E924` 随即设置 END。
下一次中断 `08:3B60` 先检查 END，直接进入 `39B6 → 39D0 → 24:9AB8`，
跳过 `3B88 → 24:98FC` 的换缓冲，因此未播放已排队的最后一颗。

修正为明确两阶段占有：交付最后一颗时仍保持真实压缩帧占有和未结算状态；
下一次 step 才结算一次实际输入、回收并返回真实无更多 PCM，不假报额外声音。
此时原厂已经在 `24:993E/9992` 换到最后一颗，之后才经 `08:3C22` 调用填充服务。
不修改原厂 END/EOF/EN，不造额外占用字节；同样适用于未截短的完整最后帧。

修正版构建：

- QEMU `ef435f24d334d90706bf8daeb4112bb8e31866e932a4abeee63ed98dd37b2f2b`；
  相比首轮 C 仅改了实现说明注释，guest ring 逻辑在新 ROM 内。
- ROM `tmp/np560-mp3-hle-final-factory-20260908-v2/resident.bin`，
  SHA256 `d03bdb9ea1cc6a5b7fb332b3c10eda6a023ab2ab95c55830317c4958a3f7aade`；
  manifest 明确 `final_input_retirement=next-step`，服务 gate 位置不变。
- `tmp/np560-mp3-final-word-tail-20260908-v2`：原厂三帧实际 1252 字节输入通过，
  所有末帧输出阶段均不提前 END，重复查询不回收，下一步准确结算且容量恢复。
- `tmp/np560-mp3-final-even-lsf-20260908-v2`：MPEG-2 四帧共 418 字节，完整偶数 EOF
  也保持末帧占有至下一步；每路 2304 样本，对 FFmpeg 最大差 1。
  单帧先行用例的 guest 控制检查通过，但 FFmpeg 拒绝仅一帧的输入片段，因此该先行报告
  保留为失败，不计作 PCM 对照通过；四帧用例没有这个参考工具边界。
- `tmp/np560-mp3-final-gate-20260908-v3`、`tmp/np560-mp3-final-standard-gate-20260908-v3`：
  最终同构构建的 7 项 final gate、8 项普通入口/ABI、4 项错误配置拒绝均通过。

仍需保留边界：原厂无更多 PCM 路径会清 `BIT31.6` 等状态，功放 GPIO 的声学意义未恢复。
即使 DTU 最后一颗补齐，也不能单凭此宣布真实功放尾部、无缝交接或 M2 已完成。

## 修正版整机复测

`tmp/np560-mp3-final-player-20260908-v2/report.json`，同目录 `delivery-analysis.json`：
最终构建、只读同一 NAND、原厂导航与播放器、`icount=0,instruction-clock=on`，12 次观察，退出 0。
累计解码 249 帧/498 颗；两次释放前各为完整 116 帧/232 颗，实际 DTU 各为
**132480 样本/路、230 颗**。相较首轮 v5，两轮均新增实际最后一颗 576 样本；
剩余两颗差额对应此前已确认的启动覆盖，不能把它计入末尾。
解码、空间查询、PCM 复制、末帧四类错误均为 0，实际 final 调用 2 次。

独立只读波形核对：两轮、两个声道的源 `[1152,133632)` 全部 130688 个变化值精确相等，
WAV 对应 `75363..219582`、`226486..370704`；frame 115 的两颗单独核对也完整匹配。
关 DAC 的累计 DTU 写入分别为 132480、264960，和两轮每路 230 颗一致。
这证明本例缺失的最后一颗已交付，不再只凭解码数量判断成功。

录音 396631 帧、8.263146 秒，无采集缺口，左右有 1 个呈现帧不同；PCM SHA256：
`a3917fbb0986a44d748caad5e9aa258870ebd710d2051339e63c74c4b1181716`。
两次零区间仍各 143.833333 ms，DAC 关闭分别 93.296292/93.287958 ms，
**本修复没有消除交接静音，也没有验证无暂停 Web 实时播放**。
连续零区间包括源文件自己的末尾零样本，不能把全部 143.833333 ms 归为播放器额外间隙。
参考最后非零样本 `133608=-2` 在两轮均实际出现；其后 23 个源尾零约 0.522 ms，
已合并在上述零区间中。启动覆盖和功放 GPIO 的边界仍保留，不以波形通过取代完整 M2 验收。

本轮没有修改用户 Web 或默认配置，没有复制或保存 NAND；所有自有测试实例均正常退出。
