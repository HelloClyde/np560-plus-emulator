# NP560+ 完整模拟器实现计划

更新：2026-10-02。此文件只记录当前计划，不累加实验流水账。

完整整机目标仍未完成；默认播放器 ROM 为 v6，v8 EQ 包仍是实验配置。
以下局部证据不能拼接成“最新统一版本全部通过”，也不能证明逐周期等同真机。
原计划的完整历史保存在 [2026-09-22 归档](history/plan-2026-09-22-before-current-state-cleanup.md)；
具体地址、试验版本、失败日志和复现命令继续放在专题文档。

## 1. 目标与原则

**以 QEMU 忠实实现 NP560+ 整机，通过 Web 操作原厂系统，完整使用原厂应用和游玩 NPE 游戏。**

交付的是同一套可安装、可重建、可长期使用的虚拟设备，不是菜单演示、单款游戏补丁或自动化测试平台。
NPE 是优先打通的核心用途，但不是整机实现的范围上限。

“完美实现”需要同时满足：

- **硬件正确：** CPU 指令、寻址、DSP、内存、异常/中断、时钟与外设行为完整；不只覆盖已经运行过的代码。
- **系统完整：** 原厂系统正常启动，菜单、窗口、输入、显示、声音、文件及应用服务实际工作。
- **游戏完整：** 从“开始 → 娱乐 → 游戏世界”进入真实 NPE，正常游玩、发声、保存、退出，重启后继续。
- **资料可靠：** 原生文件与存档持久保存，内容可交换，升级、关机、恢复不会破坏资料。
- **独立可用：** 普通使用不需要调试器、运行中 RAM 注入、离线修 NAND 或切换实验专用构建。

没有真机和完整原厂 mask-ROM 转储，当前不能证明逐字节、逐周期等同真机。
目标不因此缩小：能恢复的继续恢复，无法核对的明确标为未知；不能把行为兼容宣布为真机完全一致。

## 2. 架构不能偏离

| 层 | 应实现什么 | 不采用的替代方式 |
| --- | --- | --- |
| QEMU CPU / SoC | 指令、总线、内存、SFR、DSP、异常、中断、时钟、传输 | 按游戏名或程序地址强改执行结果 |
| resident ROM | 有原厂字节的继续执行；01/02 缺失服务允许按 ABI 实现 HLE，包含状态与副作用 | 未知入口一律成功、假 ready、把 HLE 宣称为原厂 ROM |
| 外设 | LCD、物理键盘、音频、NAND/ECC、RTC、电源及本机实际接口 | 固定 ready、忽略状态变化、按某张截图修数据 |
| Web | 显示实际 LCD，传递物理输入，播放设备音频，管理虚拟设备 | 补画菜单、擦除残影、修改选中项或游戏状态 |

ROM 的原厂字节、依据调用契约重建的 guest 代码、HLE 服务、临时桩和未知入口必须区分。
PRG 中有可复用代码，不等于升级包包含完整 mask ROM；重建镜像也不是取得了原厂 ROM 转储。
HLE 是被允许的软件服务实现层，不用于掩盖通用 CPU、总线或外设错误。
仅对已登记的 01/02 缺失服务生效；不能顺手启用旧诊断菜单、逻辑键注入或改写其它程序执行结果。

当前需要避免的误判：

- 英雄传奇屏幕坐标不变不一定是方向键失效：世界坐标须加视口偏移，Up滚屏反例已澄清。
- 按键提交、服务端ACK、guest消费和应用动作是不同阶段；详细观察关闭时不能用零/旧计数下结论。
- v8游戏→MP3证据使用原厂设置关闭游戏音效，且完整追踪明显拖慢运行；不是实时速度或游戏发声证明。
- 默认v6本机播放器窗口约实时只覆盖被测曲目和配置；完整观察下的游戏→MP3路径不能作为游戏速度或浏览器听感证据。短按仍有一次独立实例漏按反例，不能因性能提升宣称全部输入可靠。
- 当前 NAND journal 已跳过 data/OOB 均为 FF 的空擦除同步：独立持久化测试与《天降风云录》原生保存/冷读通过，启动首键的隔离反例在新构建上一次通过。旧新构建不是严格单差异 A/B；普通网页连续短按和其它负载仍需验收，不能以此宣布输入问题全部解决。
- 该新构建的后续三次独立冷启动首次 150 ms F4 均被消费；两条原厂菜单路线、其中一条第一槽读档和地图四方向也以 150 ms 逐键通过。证据见[点按时序](web/np560_pointer_debounce.md)；真实网页触控和长时重负载仍需验证。
- Edge 移动视口的两次隔离浏览器实测已覆盖真实触控 F4/右键及鼠标“开始”到客机消费，均单次映射且释放重新待命；这是桌面 Edge 的触控模拟，不代替物理手机、长时游戏和各键位验收。隔离页空闲全空白的失败样本已与启动页分开记录，见[点按时序](web/np560_pointer_debounce.md)。
- 当前核心的第一槽覆盖/取消与 NAND 日志冷读回已由两个正常退出的 QEMU 进程确认；只覆盖一个已知游戏进度，不代表全游戏/全槽或断电恢复。启动页一次 250 ms 短按仍漏掉，原厂候选到达后释放则成功；需单独解决实际用户短按可靠性。
- 24kHz单声道的FFmpeg尾部对照差异，在独立mpg123对照下表现为参考实现分歧；保留原失败和阈值，不盲改解码器。
- Info快进失败涉及原厂帧头original位比较；尚未解决，不能以替换MP3解码器或改称Xing就宣告修复。
- HLE输入校验失败残留旧PCM可用标记已修复；默认v6错误→释放→重开检查通过。
  MPEG1忙碌请求不破坏第二granule、empty不重复发布的服务层检查也通过。
  这是服务层恢复，不等于原厂播放器损坏歌曲→下一曲的整机验收；证据见播放器文档。
- 原厂播放器已实测受控坏帧：保留1次坏侧信息及2次缺历史错误后继续同曲到811帧，
  未观察到弹窗/挂起；连续音频和错误后选下一首仍待验，不能把观察通过当完整播放通过。
  选曲探针已按当前列表修正并保持精确行校验；同进程正常短曲24帧/48granule完成，
  其会话内捕获真实非零DAC，随后自动返回原曲。连续16.75秒DAC无采集丢段，但自动
  换曲存在约358ms静音，其中原厂50/200ms等待保留；约97ms关闭期仍待定位。
  无缝/真机音质、所有坏文件及播放模式仍未验收，详见播放器文档。

## 4. 实现路线与交付条件

阶段按功能依赖推进，不要求先穷尽全部 CPU 指令才运行应用。
CPU、ROM 和外设缺陷在阻断功能时立即修复，不统一拖到最后。

| 阶段 | 要完成的实现 | 完成后用户能做什么 |
| --- | --- | --- |
| M1 系统正常操作 | 显示刷新、物理输入、菜单/窗口切换、资源交接 | 正常点按、保持、返回即可操作原厂系统，不花屏、不失控、不依赖特殊节奏 |
| M2 原厂声音 | 声音 ROM 服务、实际格式/算法、DSP 与缓冲/中断依赖 | 音乐播放器播放真实支持内容；NPE 开声音仍可运行，音量及播放控制有效 |
| M3 NPE 完整游玩 | 装载/退出、剧情、地图、战斗、技能、物品/装备、声音、原生存读档 | 从系统入口游玩至游戏正常结束条件；关闭模拟器再启动仍能继续存档 |
| M4 原厂应用完整使用 | 按固件实际目录补齐学习、辞典、输入法、记事、文件、媒体、设置等功能 | 各应用完成真实用途，包括需要的内容装载、编辑、保存与重开 |
| M5 完整设备生命周期 | 存储、真实接口、RTC/电源、关机/唤醒、升级恢复 | 交换内容、长期保存资料、正常管理电源并升级恢复 |
| M6 统一完整交付 | 清退临时桩和特判，补齐剩余硬件行为及错误路径，统一构建与管理 | 同一版本独立可用、可维护；剩余未知项明确披露 |

**以上阶段均未整项完成。** 原有局部成果保留，不因重新规划而重做。
单款通关不证明所有 NPE 兼容；能打开某个应用也不等于该应用已经实现。

- 恢复启动、调度、内存/对象、绘图、文件、输入和媒体服务，包含共享状态、释放与错误处理。
- 当前声音重点是流初始化、处理、续填、停止及表模式服务，不仅补出一个可返回的入口。
- 查明实际格式、帧结构、算法、系数和输出规则；候选算法名字或相似码率不是匹配依据。
- 恢复“原始内容 → 原厂应用/ROM 服务（允许 01/02 HLE）→ guest PCM 缓冲 → 音频设备 → Web”整条链；
  HLE 解码不等于宿主播放器，不能直接播放原文件冒充完整模拟成功。
- 同时清退已知临时桩；依据不足的部分保留明确缺口，不盲填算法或推测常量。

- 显示错误沿原资源、内存对象、绘图、总线、LCD、Web 逐层查，不在前端补像素。

### NPE 与全部原厂应用

- 完成 NPE 列表、装载/重定位、运行、退出与资源释放；覆盖真实玩法而不是只有标题或地图。
- 完成原生存档状态、槽位、覆盖/取消、读档、失败处理和跨游戏隔离。
- 按固件目录落实其它应用的实际用途及共用服务；不添加按应用名生效的硬件补丁。
- 缺课件/词库与远端服务停服分别记录；仍实现设备侧协议与正常失败行为，不伪造联网成功。

### 存储、接口、电源与整机交付

- 补全 NAND data/OOB、擦写、busy/状态、ECC、错误处理及原厂文件增删改。
- 分清 guest 写入成功与宿主持久化保证；保护正常退出、异常中止后的资料。
- 完成本机实际 USB/其它接口、内容交换、loader、原厂升级与恢复；研究用 RAM 传输桥不算真实接口。
- 完成 RTC、电池/ADC、外接电源、复位、关机、休眠和唤醒。
  已核对关屏路径的内部 17BC 为 PLL/CLKCON 保存恢复代码，暂写 E418 不设置
  OPMODE；不能以解除低功耗拒绝代替实现。后续区分 LCD 关屏、GPIO 轮询与
  CPU 停钟，依据见[电源时钟边界](hardware/np560_power_clock_boundary.md)。
  已在同进程经原厂关屏/唤醒后选曲、按键调音量，采集到约15秒连续非零
  DAC音频；这是该播放交接通过，不是断电RTC、真休眠或浏览器听感完成。
- 一致快照必须同时保存 CPU、RAM、设备、时钟、传输及 NAND/日志时间线，
  不能将旧 RAM 与新 NAND 混用；全部接齐之前保持不完整快照保护。
- 统一 QEMU、ROM 重建、内容导入、设备配置和 Web 启动；给出安装、操作、声音、保存、备份与恢复说明。

## 6. 避免再次把工具当目标

画面比较用于确认显示错误；自动导航用于复现操作；压力测试用于已发现或合理怀疑的累积状态问题。
它们有用途，但都是验证手段，不是模拟器的功能，也不是独立交付阶段。

- 不设自动导航平台、截图平台、千次压力测试或脚本数量目标。
- 优先复用现有工具；只有当前缺陷无法观察时才补最小诊断，取得证据后回到实现。
- 每项修改做与风险相称的验证，确认原厂实际用途；不以 ACK、无报错、退出码或测试音替代结果。
- 汇报固定为：**缺失行为 → 原因/依据 → 实现变化 → 新增能力 → 剩余缺口**。
- 新的逆向结论是进展，但与功能完成分开记录。没有新证据时，不反复检索已排除来源或重跑已通过流程。
- 若当前缺口确实缺资料，写清需要什么证据、影响什么功能，先做音频内其它能约束该缺口的检查。
  如必须转向其它功能，先明确告知用户卡点及拟切换事项，不将暂时缺证据自动当作换方向的理由；不能用绕过结案。
- 保护用户正在运行的实例和存档。验证使用隔离设备，不因连接失败擅自重启用户实例。
