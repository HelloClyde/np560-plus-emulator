# MP3 原生解码性能改进

日期：2026-09-07。目标是原厂播放器实际连续播放，不是宿主解码或离线生成 WAV。
完整整机、原厂应用和 NPE 的范围保持不变，NPE 专有声音不由 MP3 替代。

## 第一步：精确的 32 × 32 → 64 位乘法

完整播放器前一现场的粗采样 PC 主要落在 hybrid、synthesis 和共享算术代码。
初版采用直接矩阵点积，每项还要对输入取绝对值、保存三个寄存器、再恢复结果符号。

本次修改三个生成器：

- `scripts/build_np560_mp3_antialias.py`：重写 `multiply_positive`，并增加 `multiply_signed`。
- `scripts/build_np560_mp3_hybrid.py`：去掉重复的系数取绝对值和完整结果取负。
- `scripts/build_np560_mp3_synthesis.py`：带零检测的乘法入口尾调用完整有符号乘法。

新实现仍是 DMCU 指令，使用四个无符号 16-bit MUL 和多 word 进位；
先形成无符号 64-bit 乘积，再按原始操作数符号修正高 32 位：

```
signed(x) × unsigned(y) = U(x) × U(y) - (x < 0 ? U(y) << 32 : 0)
signed(x) × signed(y)   = 上式           - (y < 0 ? U(x) << 32 : 0)
```

等式按 64-bit 二补码模数计算；没有提前舍入/截断，INT32_MIN 也不需要绝对值特判。
只保存一个工作寄存器，保持原先 R8..R14、DS/SOCR 契约，R4..R7 仍为允许破坏的临时值。
不修改 CPU 指令语义、采样率、定时器节奏、音频数据来源或原厂等待逻辑。

### 首版失败及修正

`tmp/np560-mp3-fast-multiply-20260907-v1/` 是保留的失败记录。
最初将 x 的高半字放在 R5，忽略 R5 低字节属于 ARX、每次 MUL 会更新它，导致全幅测试不符。
修正为在保存的 R8 中保留高半字，四次乘法后才恢复到临时 R5。没有改 CPU 去迁就错误代码。

## 第二步：移植 libmad 快速 DCT32

已新增 `scripts/build_np560_mp3_dct32.py`，将固定来源的 `synth.c:dct32`
快速分解生成 DMCU 指令。原函数 SHA256 为
`c7a49ee84744f3d6a7ef2fa5be69bfc3d65056b9748fc58978843df0deafd5f5`，
来源与许可证仍见 `doc/sources/libmad-20260907/`。不是原厂 ROM 字节恢复，
不是通用编译器，也没有在 QEMU/宿主截获调用代算。

旧矩阵每个非零 slot 需要 1024 次 32×32 乘积；新分解使用 80 次乘法、
80 次加法、129 次减法和 49 次倍增。每次新乘法的宽度和开销不同，
不能直接把 1024/80 当作运行提速倍数。

### 范围、状态与工作空间

- 保留全宽 signed int32 Q23 输入；177 个临时数用 signed 48-bit 保存，
  乘积用 80-bit，乘法后 floor >>28，输出时才转为 Q17。无输入缩幅、
  提前裁剪或丢弃合法大值。构建时用精确有理数系数和传播舍入误差检查全部表达式：
  中间值幅度界为 2^36，V 输出幅度界为 2^30+1，均在对应存储宽度内。
- 输出完整 V64；显式处理 hi/lo 排列、先取负再舍入和镜像。
  窗函数、1024 项 V 环、PCM 舍入/饱和、左右声道历史的结构不变。
  新 Q28 分解和旧 Q26 矩阵的舍入点不同，**不要求二者逐位相同**；
  对照使用独立编译的原始 C 函数，以及数学/libmad 浮点和 FFmpeg。
- 独立 DCT 工作区 1062 bytes；合成总工作区为 1102 bytes。
  完整解码器复用原先 reorder 搬出后不再使用的 SCRATCH 0x3300..0x374D，
  位于 OVERLAP 0x3C00 之前，不扩大堆租约，不覆盖仍活跃的谱、历史或输出。
- 可选 `--fast-dct32` 才启用，默认矩阵路径保留。整理条件生成后两种
  synthesis 代码 SHA 均与整理前相同，没有通过删除测试来改变基线。
