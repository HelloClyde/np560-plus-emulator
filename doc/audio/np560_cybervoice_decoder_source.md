# 已取得 CYBIT 旧版解码器，但不能作为 NP560 ESAC-4 的现成实现

日期：2026-09-07。状态：**取得可分析的解码程序；NPE 实际解码和播放仍未恢复**。

## 1. 这次不再只有产品介绍

通过 [历史官方 CyberVoice E-mail 产品页](https://web.archive.org/web/20001027074229/http://www.cybit.com:80/cbvmail.htm)
的试用包链接，取得部分归档数据，从中解出内部 CRC 校验通过的完整 CBVPlayer.EXE。
它是 Cybernetics InfoTech 的 PC 播放器，不是诺亚舟程序或芯片 ROM。
外层安装包仍截断，不能称为“完整 SDK 已取得”；来源、哈希和失败边界见
[来源记录](../sources/cybervoice-2000-20260907/README.md)。

播放器版本资源显示 CyberVoice Player Version 2.0、1996–1997 版权，内部 FileVersion 为 1.0.0.1。
其导入是 Windows API，已定位的音频解码使用 EXE 内代码和数据表，不需要另一个 codec DLL。
这里的意思是已经找到解码算法可分析的机器码；没有执行整个 EXE 或证明其输出与 NP560 一致。

## 2. 静态核对的帧契约：105 bit → 168 samples

本节全是 **x86 PE 虚拟地址，ImageBase=00400000**，不是 DMCU 的段地址。
播放器 SHA-256：`e20d6097cc31c2cdc3f9c6961386c609fd8aa147c0c14145cb83c96e8d4ec7eb`。
相关原指令存于 [反汇编片段](../disassembly/np560_cybervoice_5k_decoder.asm)。

`00403386..004034DD` 调用 `00403270` 提取一组固定宽度字段；后者处理双输入缓冲边界，
最终由 `004030EE` 逐字节移位、读出低位在前的字段。正常输入分支的字段组为：

| 目标 word 数组 | 个数 × 每项位数 | 合计 bit |
| --- | --- | --- |
| 00431430 | 3 × 8 | 24 |
| 00431436 首项 | 1 × 8 | 8 |
| 00431436 后两项 | 2 × 5 | 10 |
| 0043143C | 3 × 5 | 15 |
| 0043145A | 3 × 7 | 21 |
| 00431442 | 12 × 1 | 12 |
| 00431460 | 3 × 5 | 15 |
| 合计 | | **105** |

`00401EA9` 每轮先调用以上位字段读取，再调用 `004017FC` 做声音合成。
随后 `00401EFE..00401F53` 遍历 **0xA8=168** 个浮点结果，饱和至 signed 16-bit 后写入 PCM；
外层可重复多个块。调用者 `00402D28` 调该函数，`00402D3A` 将块数乘以 **0x150=336 bytes**
报告输出量，与每块 168 个 16-bit 样本一致。

官方产品页和包内帮助说明为 **5 kbit/s**；在其 8000 Hz 条件下，
`105 / 168 * 8000 = 5000 bit/s` 与指令吻合。该核对未运行解码函数，未生成声音。

## 3. 与 NP560 的关系不能跳步

- 这是一个真实可逆向的同供应商旧版解码实现，可以分析位流、预测器、码本等具体结构。
- 本次定位路径固定为 105 bit / 168 samples，不是已确认支持多档的 ESAC-4 实现。
- NP560 format 13 为 8400 bit/s / 8000 Hz，9..18 十档与后来的官方 ESAC-4 完整匹配。
  不能因为供应商相同，直接把这个 5 kbps 解码器接到 `01:B7AA`。
- NPE 每帧 21 bytes / 160 samples 仍是此前有条件的推导；本次旧版播放器不证明也不改写它。
- 未恢复 `B6DE/B7AA/B816/B84E`、`ACD8/AD92`，没有修改 QEMU/重建 ROM/NAND/Web，
  MP3 解码缺口也未发生变化。

## 4. 后续动作边界

[当时的官方核心技术页](https://web.archive.org/web/20001018000055/http://www.cybit.com/Core_Tech.htm)
明确提到 C、定点 C、DSP、Windows DLL 以及 DOS coder 评估程序，但评估获取方式为联系厂商，
不是该页提供了公开下载。授权目录仍链接到 ESAC/LRC 等介绍，未取得 ESAC 评估 EXE。

下一优先对象是 **ESAC-4 的评估程序、运行库，或包含它的诺亚舟内容制作／转换工具**。
若只继续分析这份 CyberVoice，必须先提出能检验与 ESAC 关系的具体问题；不能为了多一个
能发声的程序而实现、演示整个旧版 5 kbps 播放器，更不能用它替换模拟器中的原始 NPE 音轨。
