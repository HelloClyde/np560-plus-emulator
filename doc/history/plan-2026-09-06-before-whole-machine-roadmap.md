# NP560+ 完整整机模拟器实现计划

更新：2026-09-06。按“完整、忠实的 NP560+ 整机模拟器”推进；完成项须关联实际构建和原厂使用链证据。

计划只围绕“还缺什么设备能力、如何实现、用户最终能做什么”安排工作。
自动导航、画面比较和压力测试是修复后的验证手段，不是待交付功能，不单独计入进度。
本次重排保留已有实现和证据，取消以工具建设、固定测试次数或重复证明已通过路径为主线的安排。

**功能交付顺序：原厂系统可日常操作 → NPE 完整游玩、原厂声音与存档 → 全部原厂应用 →
完整外设与设备生命周期 → 整机兼容性和忠实度收尾。CPU/SoC 和 ROM 恢复贯穿每一步。**

当前实施重点是解除原厂音频/流服务缺口，并收尾实际阻塞操作的系统问题；
不是先做完一轮泛化菜单压力测试，才开始补声音或游戏功能。

## 1. 总目标与完成定义

**用 QEMU 完整实现 NP560+ 的 CPU、SoC 和外设，让原厂系统、原厂应用及真实 NPE 游戏正常运行，通过 Web 操作整台虚拟设备。**

“完美实现”指向原机的完整功能和正确行为，不是菜单截图相似，也不是某个游戏能启动。
NPE 完整游玩仍是核心优先交付，但不能代替整机完成。最终必须同时满足：

- 正常开机进入完整原厂桌面；全部菜单、物理按键、窗口、时钟和状态指示正确。
- 学习、辞典、网络、记事、系统及开始菜单下的实际应用能完成工作，并正常返回。
- 从“开始 → 娱乐 → 游戏世界 → NPE 游戏”进入真实游戏，正常进行玩法、场景切换、
  声音、原生存档/读档、退出和重开；兼容机制不同的游戏，不为单个游戏特判。
- 音乐播放器真正播放和控制音乐；实现原机具备的其它媒体与输入功能。
- 内容导入、文件管理、设置保存、关机重开、休眠唤醒、升级和恢复可用，不需要开发者改 RAM 或修 NAND。
- 同一套通用实现支持以上功能，没有用伪成功 ROM 桩、跳过初始化或前端补画掩盖的设备缺陷。

交付分成“功能完整”和“忠实度确认”两层：前者要求用户实际完成原机用途，后者要求
底层行为有原厂代码、资料或真机证据支持。功能暂时能用，不代表底层实现已准确；
尚无法核对的行为保留在待确认清单，不用“完美”一词提前结项。

目前没有真机和完整原厂 mask-ROM 转储。逐周期精度、未公开寄存器及部分原厂行为仍需证据，
不能宣称已与真机完全一致。未知项是未完成工作，不从目标范围删除，也不凭空标为已实现。

## 2. 固定架构与 ROM 恢复原则

- **QEMU 硬件层：** 执行 DMCU 指令，模拟内存/总线、寄存器、中断、统一虚拟时钟和外设。
- **Guest 软件层：** 原厂固件与有依据重建的 resident ROM 执行装载、调度、绘图、文件系统、解码、应用和游戏。
- **Web 前端：** 显示 LCD 输出，传递物理键按下/保持/释放，播放 guest 音频，提供设备及内容管理。

不在 Web 重画菜单、擦时钟残影、决定菜单选择或实现游戏逻辑；不在宿主拦截 ROM 调用
代做解码、文件分配或返回虚假成功。不靠按键限速、宿主 sleep 或刷新频率掩盖时序错误。

ROM 服务逐项区分 **原厂字节 / 证据支持的行为重建 / 临时桩 / 未知**。
先查原包装载/重定位和可复用原厂实现，再由调用者及结果消费者确定参数、状态、
内存所有权和硬件副作用。缺少关键证据时保持未知；PRG 中有函数、常量或升级包标注 MASKROM，
均不能单独证明已取得完整片内 ROM。最终清除无依据的临时桩、别名和特判；
不能只清理一条演示路线，而把其它应用会调用的入口留作伪成功。

## 3. 当前能力边界

以下来自已有记录，不表示这些结果已在同一发布版本全部通过。

| 领域 | 已有基础 | 仍未完成 |
| --- | --- | --- |
| CPU / SoC | 原厂代码可执行，部分寻址、中断、Timer、DTU、DSP 和环形缓冲已有验证 | 完整指令/寻址/异常、设备模式和时序；部分寄存器与标志语义待证 |
| resident ROM | 复用部分原厂代码，重建部分服务 | 不是完整原厂 ROM；共同流服务缺失，构建脚本仍含直接返回的临时服务桩，映射与副作用需逐项确认 |
| 原厂系统 | 开发构建可冷启动到完整桌面；旧顶栏素材换序、Web 点按漏键和 Reset 回滚已有修复记录 | 旧普通输入重复消费现场及其它跨应用问题未全部闭合；不能据历史故障断言当前构建仍有同一缺陷 |
| NPE | 原厂关闭音效后可进入《英雄传奇》第一场景、移动和退出重进；第一槽非默认位置已通过原生保存、落盘和新进程读回 | 声音开启入口仍有 ROM 缺口；完整玩法、其它存档状态/槽位及更多游戏尚未贯通 |
| 音频 | DAC → PCM → Web 输出和若干原厂样本处理函数已有验证 | 音乐播放器、NPE 原厂解码与实际声音尚未完成 |
| 存储 / 使用入口 | 原厂烧录、ECC、文件 API 导入读回已有证据；Web 可用 | 完整持久化、设备传输、生命周期、整机快照和发布流程尚未完成 |

已修复一个生命周期问题：`np560_machine_reset()` 不再重新装载初始 NAND，
原厂音效设置经过确认、普通 Reset 后保留；随后也通过 NAND 落盘、结束进程、全新进程冷启动
和再次打开设置读回。详见 [原厂设置持久化](np560_native_settings_persistence.md)。
《英雄传奇》第一槽的非默认位置也已通过跨进程原生恢复；其它设置、资料和完整游戏状态仍待完成，
不能据此宣布持久化整体通过。

已定位的旧顶栏花屏来自 NAND checkpoint 混合字节顺序；另有 IGNDS 错银行写入修复。
不能把已定位故障重新归为“缺绘图 ROM”，也不能据此宣布全部损坏已修。
旧版本局部游玩不算当前版本游戏通过；端口号不是版本号。

当前明确的底层阻塞是原厂声音开启路径的 resident 服务：最近记录先停在 `02:ACD8`，
后续共同流服务 `01:B6DE/B7AA/B816/B84E`、`02:AD92` 仍需恢复；
`01:4674/46CC/46D0` 还有直接返回的临时桩。入口地址标识待研究对象，
不代表已经知道其全部算法，也不代表只补完这些入口就完成整机。

已有 [Web 点按时序修复记录](np560_pointer_debounce.md)，但这只是输入的一项局部修复，
不代表原厂连发、跨应用输入或当前用户实例均已正确。具体时序和适用构建留在专题文档。

另已修正普通 [MUL 小数模式及 V 标志](np560_multiply_fractional.md)：原来的有符号乘法忽略 FR，
MUL/UMUL 留下旧溢出标志。属于 M0 的 CPU 正确性修复，不计作原厂音频 ROM 已恢复。

[跨页取指一致性](np560_code_coherence.md) 也已修正：guest 改写跨页立即数后不再执行缓存旧值。
旧按地址同步及其它映射仍待清退，不据此认定全部代码损坏或原厂装载问题已解决。

## 4. 功能里程碑

M0 是贯穿全程的底层实现主线，M1–M5 是可交付的整机能力。
共同依赖按实际阻塞交错推进，不要求先研究完全部硬件才能运行应用，也不因应用暂时可用就跳过底层缺口。
目前没有任何一项被本计划认定为完整通过。

### M0：CPU、SoC 与 resident ROM 实现完整

补齐合法指令和寻址、状态标志、内存视图、调用/返回、中断、定时器、数据传输及外设行为。
恢复原厂启动与装载关系，确认 ROM 入口、参数、状态、缓冲区所有权及硬件副作用；
对现有代码逐项区分原厂字节、行为重建、临时桩和未知，清除影响正确执行的临时实现。

**交付物：** 可执行原厂代码的通用 QEMU 设备模型，以及来源和行为边界明确的 ROM 镜像构建流程。
CPU 或 ROM 的实现不能按菜单名称、游戏名称或宿主调用者特判。

**完成条件：** 已知合法行为和必需服务没有未实现缺口，正常与错误路径都得到处理；
不能用“没有遇到未知指令”推断 CPU 完整，也不能用“没有触发 ROM 缺失”推断 ROM 已恢复完整。
没有证据核对的硬件或 ROM 行为继续列为待确认，不冒充原厂实现。

### M1：原厂系统稳定可操作

实现正常启动、五类一级菜单、开始菜单、应用进入/返回和正确的状态维护。
修复普通按键重复消费、切换时资源/代码损坏，以及 LCD 局部更新、选中态、弹窗和时钟残影。
短按、长按、释放、组合键和失焦释放均走真实矩阵与原厂调度。
同时完成基础设置的确认、取消、保存和重启读回；区分普通复位、关机重开与显式恢复初始镜像。

**完成条件：** 正常开机后自然操作菜单、进入应用、退出并继续操作，画面和状态正确；
不依赖单扫描注入、手改状态或特殊操作节奏，已保存设置在正常重启后仍可用。
已知菜单、调度或基础持久化缺陷未关闭时，M1 保持未完成。

### M2：NPE 完整游玩，打通共用声音和保存能力

贯通原厂 loader、重定位、运行时和资源加载，补齐使用链所需的 ROM 与硬件能力。
实现原厂流处理/解码、缓冲、样本传输、DAC 和游戏计时；完成玩法、输入、场景及资源释放。
原生存档通过 guest 文件系统写入 NAND，重开设备后可正常读回。
音乐播放器复用同一媒体和存储机制，落实播放、音量、暂停/继续、停止及退出。

**完成条件：** 从原厂菜单进入《英雄传奇》，完成有代表性的实际玩法、声音、
原生存档/读档、退出、再次进入和关机重开恢复；随后扩展机制不同的真实 NPE。
标题页、局部走动、关闭声音、跳过初始化或用整机快照代替原生存档均不算完成。

### M3：原厂应用功能完整

依据实际固件目录和资源逐项覆盖学习、辞典、网络、记事、系统及开始菜单应用。
完成内容加载、输入、查询/编辑、设置、保存、取消、错误提示和返回，不止打开窗口；
补齐原机具备的其它媒体与输入功能，各应用共用硬件和 ROM 实现。

**完成条件：** 应用能完成实际用途，跨应用操作不损坏资料或设备状态。
内容缺失、外部服务停服和模拟器缺陷分开记录，不伪造在线原厂服务，也不把未验证功能写成可用。

### M4：完整设备生命周期与外部接口

实现原机具备的 USB/其它传输接口、原厂 loader 与升级路径、文件交换及管理；
补齐 RTC、电池/ADC、外接电源、关机、复位、休眠与唤醒。
完成 NAND 文件增删改、提交与异常恢复，以及 CPU、RAM、外设、定时器的一致快照恢复。

**完成条件：** 用户能建立、使用、保存、升级和恢复设备，不需要调试注入。
明确区分游戏原生存档、NAND 持久化和整机快照；正常开关机和保存随前面阶段提供，不拖到本阶段才开始。

### M5：整机兼容性、忠实度与可交付版本

补齐前面场景未触发的合法指令、异常、外设模式、ROM 服务及错误路径；
核对时序和资源生命周期，清退无依据别名、成功桩及游戏特判。
提供可重复构建、镜像生成、统一启动、内容管理和 Web 设备控制，清晰标识正在运行的版本。

**完成条件：** 同一版本满足前述功能，已知设备侧缺口关闭，剩余不可核对行为明确披露。
没有依据时不声称逐字节或逐周期等同真机；不能以测试通过代替忠实度证据。

不要求研究完全部 CPU 才回到系统，也不因首个游戏没用到而永久忽略。

## 6. 接下来实际做什么

以下按实现依赖安排工作，不再另列一套与 M0–M5 重复的测试任务。
优先处理会破坏数据或阻断普通操作的已复现故障，其余时间用于补齐缺失能力。
已有修复保留为基线，不从头反复证明；未完成不等于已确认存在某一种缺陷。

### 第一重点：恢复共同 resident 服务，让原厂声音路径真正运行（M0 / M2）

1. 围绕 `02:ACD8` 及上述流入口追踪原厂调用者、状态读写与结果消费者，确定缺失的副作用。
   查清原包装载、重定位及可复用代码的关系；不能把 PRG 的零散字节拼接直接称为完整 mask ROM。
2. 据证据恢复初始化、流位置、数据生成和缓冲处理；分别确认十项表服务的目标状态、启停与处理行为，
   替换有依据可实现的临时桩，不用空返回、随意 memcpy 或硬编码返回值跳过。
3. 执行原厂代码时若暴露 CPU/DSP、总线、中断或传输错误，在 QEMU 对应层修复。
   接通原厂资源 → guest 处理 → 定时传输 → DAC → Web 音频；前端只播放设备输出。
4. 回到原厂声音开启的游戏入口与音乐播放器，完成真实播放、暂停/继续、音量、停止和退出。
   游戏与播放器是否采用同一格式须以代码为据；复用确实共用的机制，不强行共用未知算法。

**交付：** NPE 不再需要关闭声音才能进入，实际游戏音效/音乐与播放器内容能正常播放和控制。
当前只有数字输出通路及部分原厂处理代码可用，不提前把此项标为通过。
证据入口：[流后端](np560_resident_stream_backend.md)、[十项表模式服务](np560_resident_table_modes.md)。

### 随使用链收尾：普通输入、桌面与应用切换（M1）

- 修当前构建中可复现的漏键、多消费、释放/连发或组合键错误，保留真实矩阵和原厂调度。
  区分原厂去抖与模拟器错误；不强迫任意短脉冲都被识别，也不改变原厂行为去满足脚本。
- 对菜单、时钟和弹窗异常，沿资源装载、guest 内存、绘制和 LCD 输出定位实际损坏层。
  旧换序花屏与后续其它故障分别处理，不反复笼统归因于“绘图 ROM 缺失”。
- 完成应用进入/返回、设置确认/取消和持久化；复用已修复的 Reset 与 NAND 提交流程，
  解决实际出现的资料丢失或状态污染，不将“扩大设置遍历次数”当成实现任务。

**交付：** 用户自然操作完整桌面与应用，画面、选择和输入状态正确，已保存内容重开后保留。
若这些问题阻断声音或游戏路线，先修具体阻塞；否则不等泛化压力测试结束才推进下一功能。

### 第二重点：从局部走动推进到 NPE 完整玩法（M2）

- 沿“开始 → 娱乐 → 游戏世界 → NPE”运行真实 loader、重定位和资源装载，补齐后续使用缺口。
- 在《英雄传奇》中贯通对话/事件、物品、战斗、地图切换和持续游玩，修通用计时、输入、
  资源所有权和释放行为；各玩法以原游戏实际具备的功能为准。
- 将原生保存扩展到实际游戏状态、其它槽位、取消和失败处理；退出、重进与设备重开后继续玩。
  已通过的第一槽非默认位置跨进程恢复不重复算新进展；关闭声音的结果不替代声音开启的完整使用链。
- 用机制不同的真实 NPE 补齐剩余共用能力，不能按游戏名或当前菜单特判。

**交付：** 用户能有声音地实际游玩、保存、退出并继续，而不只是看标题页或在首场景移动。
已有有限通过范围见 [原生存读档](np560_npe_native_save.md)。

### 后续完整化：全部应用、外设、生命周期与交付（M3–M5）

- 依据原厂应用目录逐项实现实际用途：学习内容、辞典查询、记事编辑、文件管理、设置及其它原机功能。
  同时补共用文字输入、字体/资源、文件服务和媒体处理，而不是为每个窗口单独补画或注入状态。
- 完成原机内容传输与外部接口、升级恢复、电源/电池、RTC、休眠唤醒及整机状态保存恢复。
  前面阶段需要的导入、保存与正常关闭提前提供，不把基础持久化拖到最后。
- 核对尚未覆盖的合法 CPU/外设模式、异常和 ROM 服务，清除临时桩与无依据别名，处理错误路径。
- 形成同一套可重复构建、启动和日常使用的 QEMU + ROM + Web 版本，提供内容管理与清晰版本身份。
  外部原厂服务停服与设备侧协议缺陷分开说明，不伪造远端成功。

**交付：** 一台完整的虚拟 NP560+，不止 NPE 运行器；不能为先完成演示而永久裁掉第 5 节范围。

### 工作选择与停止绕圈的规则

每次实现只需明确四件事：**失败的用户操作 → 有证据的缺口 → 修改的正确层 → 新增可用能力**。
逆向是必要实现工作，但“找到一些常量/多分析了几个函数”只能报告为证据进展，不能冒充功能完成。
缺少证据时明确所需资料、尚可区分的假设与可推进的共用依赖；没有新线索不反复全盘扫描，
也不靠新增监控框架、循环导航或重复存读档消耗工作轮次。

进度报告写新增可用功能、仍失败的操作和下一项实现；不按脚本数、函数数、测试次数或无依据百分比计进度。

## 7. 验证是完成条件，不是建设目标

自动导航用于重现操作，画面核对用于发现显示差异，压力测试用于暴露有依据的时序或泄漏风险。
它们有用，但不能实现缺失的硬件和 ROM；**不设“自动导航平台”“千次压力测试”之类里程碑。**

- 修复后做能区分新旧行为的定向验证，再检查原厂使用链；次数由风险决定。
- 不再执行旧计划中的固定次数配额。只有需要排查具体的长时间运行、时序或资源泄漏问题时，
  才安排有明确失败判据的长时间运行；通过后也只说明该风险未复现，不代表整机完成。
- 显示看实际 LCD，声音听原厂内容，保存用原生读档和重开确认，不修改 guest 状态制造成功。
- 记录同一 QEMU、ROM、NAND 组合的结果，不拼接不同实验版本的成功。
- 复用已有工具，仅缺少必要观察信息时补最小诊断，不另开与功能无关的工具工程。
- 隔离实验，保护用户实例和存档，不重复生成无必要的大镜像。

能力状态只用 **未实现 / 开发中 / 部分可用 / 完整使用链通过**，同时记录适用版本和证据性质。
不以长时间无崩溃或截图正确宣布整机完成。
