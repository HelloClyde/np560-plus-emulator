# NP560+ 整机模拟器实现计划

更新：2026-09-06。按“完美实现 NP560+ 模拟器”的目标重新规划。
本文只维护整机能力、实现顺序和完成条件；历史实验、脚本建设和测试次数不决定优先级。

计划的主线是：**补全底层实现，让原厂系统和软件完成真实功能，最终交付完整虚拟设备。**

## 路线摘要

**原厂系统正常操作 → 真实声音 → NPE 完整游玩 → 全部原厂应用 → 完整设备生命周期 → 整机忠实度与统一交付。**

CPU/SoC、ROM 和外设缺口随功能依赖一起补齐，不等到最后才修底层。
当前可复现的崩溃、画面损坏和资料损坏优先处理；没有当前故障时，下一主攻项是原厂音频链。

- **最终交付物：** 一台可日常使用的完整 NP560+ 虚拟设备，不是若干互不兼容的实验构建。
- **当前最大功能缺口：** 原厂声音流/解码服务未恢复，真实音乐与有声 NPE 尚未贯通。
- **贯穿全程的欠账：** CPU/外设尚未完整、ROM 仍有临时桩，其它应用和设备生命周期未全部实现。
- **从计划主线移除：** 自动导航平台、截图平台、千次压力测试和脚本数量目标。已有工具保留复用，必要验证随具体修复进行。

## 1. 总目标：完整、忠实、长期可用的 NP560+

以 QEMU 实现 NP560+ 的 CPU、SoC 与实际外设，运行原厂固件和有依据恢复的 resident ROM，
通过 Web 使用完整虚拟设备。**目标不是主菜单演示、单款游戏演示，也不是自动化测试平台。**

“完美实现”落实为以下完成条件：

- **硬件完整且行为正确：** 合法指令、内存、异常/中断、设备状态与时序有实现，而不只是覆盖已走过的程序分支。
- **ROM 服务完整：** 所需服务及错误路径真实执行；不依赖空返回、固定成功、跳过未知代码或修改运行中 RAM。
- **原厂系统和应用可用：** 显示、输入、声音、查询、学习、编辑、文件管理等各自完成真实用途，不以能打开窗口结案。
- **NPE 完整可玩：** 从“开始 → 娱乐 → 游戏世界”启动真实游戏，正常推进剧情、地图、战斗、物品/装备和声音，
  原生保存、退出、结束进程、重新启动后继续，不破坏其它游戏或系统资料。
- **设备完整可用：** 资料长期保存，内容可交换，RTC、电源、关机/唤醒、原厂升级和恢复按设备语义工作。
- **统一交付：** 同一套构建、ROM 和镜像生成流程满足上述条件，日常使用不依赖开发者修 RAM、离线修 NAND 或手动拼接实验版本。

**NPE 游玩是优先打通的用途，不是完整模拟器的范围上限。**

完成分为两个层面，不能混称：首先让整机功能通过原厂软件真实工作；同时持续补齐硬件语义，
消除仅适用于某条执行路径的实现。只有两者均满足，才能宣布完整；能运行一个应用不是硬件完整的证明。
“周期精确”还需独立的时序依据，不能从画面正常或游戏可玩推导出来。

目前没有真机和完整原厂 mask-ROM 转储，因此不能宣称已经证明逐字节、逐周期等同真机。
功能缺失必须继续实现，无法核对的硬件行为必须明确标为未知；不能把缺少依据改写成“已完成”。
若最终只能证明行为兼容，也应如实标明，而不是降低目标后宣布“完美”。

## 2. 架构边界

| 层次 | 必须负责 | 不可用来替代它的做法 |
| --- | --- | --- |
| QEMU CPU / SoC | 指令、寻址、标志、总线、SFR、内存、时钟、异常与中断 | 按游戏名、菜单位置或程序地址强改执行结果 |
| resident / mask ROM | 启动、装载、调度、内存、绘图、文件、输入、媒体等软件服务，在 guest 执行 | 空返回、固定成功、宿主拦截调用后伪造结果 |
| 外设模型 | LCD、矩阵键盘/GPIO、音频、NAND/ECC、RTC、电源和本机实际接口 | 固定 ready、忽略副作用、为某张画面修补数据 |
| Web | 呈现实际 LCD、传递物理键按下/保持/释放、播放设备音频、提供设备管理入口 | 补画菜单、擦残影、注入选中项、代替游戏计算 |

ROM 的原厂字节、有依据的行为重建、临时桩和未知入口分别记录。
重建 ROM 不等于拿到了原厂 ROM 转储；PRG 中存在可复用代码，不证明整个 mask ROM 都在升级包里。
恢复依据必须覆盖调用约定、共享状态和副作用，不能仅凭“补完可以继续跑”。

诊断桥可以帮助观察、搬运实验数据，但不能充当最终硬件接口。
原厂文件 API 调用成功不等于 USB 传输完成；guest 写入 NAND 不等于宿主结束后资料已经可靠保存。

## 3. 当前起点

以下是已有专题证据的汇总，不是“最新统一版本全部通过”的声明。

| 能力 | 已有结果 | 仍需实现或查清 |
| --- | --- | --- |
| CPU / SoC | 原厂程序可执行；部分 DSP、寻址、标志、中断、定时器和代码一致性问题已修复；段末 PC、长指令扩展字和调用返回已统一为段内回绕；REP 与 REPB 已分离，修复原厂背景滚动丢行；明确禁用的 REP 目标已在产生副作用前停止 | 其余合法模式、映射、异常、设备状态与时序；IREP 仍未派发，EXR/向量和循环寄存器可见性仍待恢复 |
| ROM | 部分原厂代码已恢复，部分服务已有依据重建 | 声音/流服务缺失，仍有临时返回桩，无完整原厂 ROM |
| 桌面 / 显示 / 输入 | 完整桌面可显示；旧顶栏花屏定位到中间 NAND 混合字节顺序；Web 点按去抖已修复 | 自然操作、保持/连发、窗口刷新和跨应用状态不能称全部正确 |
| NPE | 无声《英雄传奇》已有地图、单眼蝠战斗、掉落、草药、第三槽同版本冷读回；《阿诺创世纪》已有部分地图/剧情、双敌战斗与逃跑、第一槽冷读回、第二槽增量保存后跨修复版本读回及跨游戏存档隔离 | 有声游玩、完整玩法与保存状态、其它内容兼容性；阿诺完整战斗/剧情/施法仍未完成，大头犬资源编号问题未结案 |
| 音频 | DAC → PCM → Web 数字输出和部分原厂样本处理已有验证 | 真实 NPE 音频、音乐播放器内容播放尚未打通；测试音不是解码成功 |
| 存储 / 生命周期 | 原厂烧录、ECC、文件 API 导入、部分设置持久化和软件 RESET 有证据；NAND 增量保存、自动合并和固定设备配置已接入，原厂设置经同一核心跨进程读回；完整资料备份/恢复命令已接入 Windows/WSL | 全部原生资料保存语义、图形设备管理、真实外部传输、电源管理、完整升级恢复及一致整机快照 |

早期英雄第二槽保存/读取使用过不同核心，不能与后来的同版本第三槽读回混称。
文件 API 导入使用过诊断 RAM 传输，不是原生 USB 传输。
较早的原厂设置增量保存记录跨越过核心修复版本；后来固定设备配置已有同一核心跨进程读回，
但两次前端文件仍有差异。两组证据分开保留，均不能据此宣称整机同构建交付完成。
具体输入、构建和实验边界保留在专题文档，不用测试次数或无依据的百分比表示完成度。

## 4. 必须完成的实现任务

下列八项共同构成整机范围，均不能因为某个样本已经运行就跳过。
按依赖关系修复通用实现，不按“做了多少脚本、走了多少次菜单”安排工作。

### A. CPU 与 SoC：执行环境完整

- 补齐合法指令及操作数形式、DSP/累加器、舍入/饱和、标志与寻址模式。
- 完成代码/数据视图、内存映射、片选、字节通道、SFR 别名、栈和可写代码一致性。
- 完成异常、中断优先级/屏蔽/嵌套/返回，以及循环与中断的组合行为。
- 统一时钟、Timer、DTU 和设备完成事件的关系，不能用固定 ready 或跳过等待维持运行。
- 已修复的 REP/REPB 不再重复列为待实现；已阻止明确禁用的 REP 目标产生副作用，
  但这仍是显式停止边界，不是 IREP 异常派发。EXR/向量、软件可见循环寄存器及其余边界/非法组合仍需恢复。
  其它指令和设备也分别标明“已实现、部分实现、未实现、依据未知”，不把未触发当作已支持。

完成条件：有依据的合法行为全部实现；未实现的指令、错误映射和时序不能再阻断原厂功能。
若资料不足以证明某项硬件行为，保留未知，不以应用可运行宣称周期精确。

### B. resident ROM：恢复真实服务，清退临时桩

- 查明 PRG、升级包、装载器、重定位/覆盖模块与 resident 入口的关系；
  区分可直接恢复的原厂代码和需要依据调用契约重建的服务。
- 补齐启动、调度、内存/对象管理、绘图、文件、输入、媒体服务，包含共享状态、副作用和错误处理。
- 优先补实际阻断功能的服务，并清查“已经返回但未执行功能”的临时桩。
  当前明确欠账包括声音流入口及 `01:4674/46CC/46D0` 表模式服务，不能因开机成功略过。
- 整理现有重建入口的来源和适用范围，清退冲突覆盖、无依据别名及历史功能绕过；
  复用已有重建脚本和 manifest，不为此另造工具平台。

完成条件：原厂调用在 guest 中执行必要行为，不依赖 RETS 空返回、固定成功或宿主代算。
若拿不到原厂 ROM 转储，交付物必须继续标明是有依据的功能重建，而不是原厂字节镜像。

### C. LCD 与物理输入：系统自然可操作

- 修复仍可复现的顶栏/菜单损坏、时间叠写、局部刷新、滚屏和应用进出后的残留状态。
  原厂资源、绘图缓冲、总线、LCD 扫描、Web 呈现逐层定位，不预设一定缺 ROM。
- 补全本机使用的 LCD 命令、灰度、扫描方向、显示/休眠、状态标记与背光行为。
- 落实实际键盘接线、按下/保持/释放、组合键、去抖和原厂连发；
  Web 失焦/断开必须释放输入，不能在前端伪造应用事件或修改选中项。

完成条件：开机、五个一级菜单、开始菜单、弹窗和应用进出可正常操作；
画面与按键来自原厂程序和模拟硬件，不需要特殊节奏或前端补画。

### D. 音频：真实播放、游戏音效和本机录音能力

- 优先查清 `02:ACD8/AD92`、`01:B6DE/B7AA/B816/B84E` 的调用契约和状态流，
  恢复流初始化、处理、续填、停止、资源释放；函数名称和算法以证据为准。
- 对表模式服务追踪实际目标状态、运算消费者和启停副作用，不能随便复制常量后返回。
- 查明真实内容的格式和算法，补齐依赖的 DSP、缓冲、传输和中断，
  打通“原始内容 → guest 处理 → 设备输出 → Web 声音”。
- 实现原厂支持的音量、播放/暂停/停止、音画同步及音频输入/录音路径；
  具体格式、接口和接线以本机资料及固件为准，不套用相似机型。

完成条件：音乐播放器能播放真实支持内容，NPE 开音效仍可游玩并发声；
本机录音用途可实际录入、保存、回放。测试音、宿主直接播放原文件或静音绕过均不算完成。

### E. NPE：从系统入口到完整游玩

- 完成“开始 → 娱乐 → 游戏世界”的列表、启动、装载/重定位、运行和退出，正常释放资源。
- 修复真实游戏中的剧情、地图切换/滚动、碰撞、角色/敌人绘制、战斗、技能、物品/装备和声音。
- 完成原生存档的必要状态、槽位、覆盖/取消、读档、失败处理与跨游戏隔离。
- 在没有开发者干预的情况下推进完整游戏流程；不同内容用于发现通用缺陷，
  不能添加按游戏名生效的 CPU/ROM 补丁，也不能改游戏数据绕过问题。
- 当前继续补尚未确认的战斗、技能、装备及后续剧情；阿诺已有滚屏修复不能算完整玩法。
  英雄“大头犬”编号异常仍待查明，不猜改资源编号结案。

完成条件：从原厂系统启动真实 NPE，有声游玩至正常结束条件，原生保存后结束进程，
重新启动仍可继续；其它可取得的 NPE 内容没有已知的模拟器兼容缺口。
单款通关或同一引擎的多个样本不是所有 NPE 已兼容的证明。

### F. 原厂系统与全部应用：完成实际用途

- 依据固件实际应用目录维护功能范围，覆盖学习、辞典、输入法、记事、文件、媒体和设置；
  记录每项真实用途、所需内容和当前缺口，不把窗口入口当功能完成。
- 落实查询/学习、中文输入/编辑、新建/删除、保存/重开和应用之间的资源交接。
- 共用的内存、文件、输入、显示或声音问题在发现时修复，不等 NPE 全部内容走完。
- 缺课件/词库与远端服务停服单列为外部依赖；设备侧协议与正常失败行为仍须实现，
  不伪造查询结果或联网成功。

完成条件：所有具备必要内容的原厂应用能完成本来的用途，进出应用不破坏其它资料；
尚缺内容的功能明确保留未验证状态，不纳入“已完成”。

### G. 存储、接口与设备生命周期：完整虚拟硬件

- 补全 NAND 页/OOB、擦写、busy/状态、ECC、错误处理及原厂文件增删改；
  原生资料写入与宿主持久化都要可靠，分别说明正常退出、崩溃和宿主断电的保证。
- 完成本机实际 USB/其它接口、内容导入导出、loader、启动选择、原厂升级与恢复；
  研究用 RAM 传输和文件 API 桥不能代替真实接口模型。
- 完成 RTC、电池/ADC、外接电源、复位、关机、休眠和唤醒及其对 CPU/外设的影响。
- 实现 CPU、RAM、外设、定时器和待处理传输的一致整机快照；
  快照不代替原厂应用存档。
  已加入 CPU 状态序列化（含双循环与嵌套中断父栈）；外设、NAND/日志时间线尚未接齐，
  整机保存/恢复暂时显式拒绝，防止继续产生不完整快照。下一步接齐设备状态与回滚策略，
  不是把“拒绝不完整快照”当作完整保存能力。见[整机快照实现边界](../np560_machine_snapshot.md)。

完成条件：设备能保存资料、交换内容、正确管理电源并升级恢复，
而不是必须常驻运行且依靠开发者修 NAND 的程序。

### H. 日常交付：同一版本独立可用

- 统一 QEMU 构建、ROM 重建、原始内容导入、设备配置与 Web 启动流程；
  明确依赖、版本、来源和使用条件。
- 复用已有增量 NAND、固定设备配置和离线备份/恢复，补齐日常管理入口；
  保护用户资料，大镜像放大容量盘，不无故复制完整 NAND。
- 日常启动和使用不依赖调试器、运行中 RAM 注入、离线修镜像或实验专用补丁。
- 给出安装、启动、输入、声音、保存、备份、迁移和恢复说明，
  在同一个交付版本上确认上述能力组合工作。

完成条件：用户可以自行安装、使用和维护完整虚拟设备。
不能把不同核心/ROM/前端版本各自成功的记录拼成一个“完整版本”。

## 5. 按可交付能力推进，而不是按测试项目推进

**先处理当前阻断使用的问题，再扩展真实能力；底层正确性贯穿全过程。**
A—H 是完整范围，不是要求先穷尽 A 才允许运行游戏的串行流程。

以下里程碑均尚未整项完成。已有局部成果继续保留，不为重新规划而重做。

| 里程碑 | 要实现的能力 | 达成后用户实际能做什么 |
| --- | --- | --- |
| M1 原厂系统自然可用 | 收尾显示、物理输入、窗口切换和资源交接的实际缺陷 | 普通点按、保持和返回即可使用桌面与菜单，不必配合特殊操作节奏，不花屏、不破坏资料 |
| M2 真实声音贯通 | 恢复声音流/解码服务及其 CPU、DSP、传输、中断和设备依赖 | 音乐播放器播放原机支持的真实内容；NPE 开音效仍可运行，播放、暂停、停止及音量有效 |
| M3 NPE 完整可玩 | 完成装载、剧情、地图、战斗、技能、物品/装备、声音及原生保存/退出 | 从“开始 → 娱乐 → 游戏世界”正常游玩至游戏结束条件，关掉模拟器后还能继续存档 |
| M4 原厂应用完整可用 | 按固件实际目录完成各应用用途，包括本机录音等未闭合功能 | 使用学习、辞典、记事、媒体、文件和设置；需要内容的功能可装载内容、操作并保存结果 |
| M5 完整设备生命周期 | 完成实际接口、持久化、电源/RTC、升级恢复、备份与整机快照 | 导入导出资料、关机/唤醒、迁移设备、升级和恢复，不依赖开发者修改 RAM 或修 NAND |
| M6 整机完整性与交付 | 清退剩余桩和特判，补齐尚未覆盖的合法硬件行为、错误路径及统一版本流程 | 使用同一套可重建、可维护的 NP560+ 模拟器；不是把不同实验版本的成功结果拼在一起 |

M2 是下一主攻项，不等 M1 的所有未知边界都研究完才启动。
任何里程碑发现当前崩溃或资料损坏，先修所属通用实现；后续阶段若是当前功能的前置依赖，立即提前。
M6 是完整性收尾，不是把 CPU/SoC、ROM 或错误处理拖到最后的理由。

### 实施队列：选择要补的实现，不选择要跑的测试

| 优先级 | 当前工程任务 | 应交付的结果 |
| --- | --- | --- |
| 立即插队 | 当前版本可复现的崩溃、花屏、输入失效或资料损坏 | 定位并修复所属 CPU、ROM、外设或前端实现，原操作恢复正常；历史已修故障不重复修 |
| 下一主攻 | 真实声音所缺的 ROM 服务、格式算法和共享状态 | 恢复 guest 中的处理代码及硬件依赖，让原始内容真正产生声音；来源不明的部分明确保留缺口 |
| 功能推进 | NPE 的技能、装备、完整战斗、剧情和原生存读档缺口 | 根据实际故障补通用实现；若原来已可用，只更新兼容性记录，不计为新增功能 |
| 整机扩展 | 其它原厂应用的实际用途及所依赖的共用服务 | 按固件目录逐项完成使用闭环，不以打开应用或走完菜单为交付 |
| 设备完善 | 尚缺的物理接口、电源、升级恢复和完整状态保存 | 实现设备模型及正常、失败、恢复行为，替换研究用传输桥和手工处理 |
| 持续补齐 | CPU/SoC 合法行为、ROM 临时桩与硬件未知项 | 随新依据补齐实现并清退替代逻辑；已有原厂程序未触发的硬件缺口也必须保留在范围内 |

每个实际开工项先明确缺失行为及其依据，结束时明确代码变化和能力变化。
逆向工作允许暂时没有代码修改，但必须产生可区分的新结论、实现契约或明确的资料缺口。
已排除的来源不反复搜索；没有具体待查缺陷时，不无限推进同一游戏或扩充测试样本。
缺完整 mask-ROM 时，继续定向取得原厂代码、SDK/文档或恢复调用契约；
若证据仍不足，说明缺失内容和影响，选择另一个有依据的实现任务，不能把绕过该服务当作完成。

### 下一项实施：解除真实声音的 ROM 缺口

1. **从已知断点继续，不重做外围设施。** 保留原始音频输入、已有输出链和严格 ROM 缺口边界，
   查明缺失服务的输入、输出、共享状态、算法和硬件副作用；来源追踪见 B、D 及对应专题。
2. **实现确定的行为。** 优先恢复可确认的原厂字节；需要重建的部分依据完整调用契约实现。
   CPU、DSP、内存或外设依赖在所属层修复，不以宿主播放原文件、固定返回成功或关闭音效绕过。
3. **以真实内容的完整生命周期收尾。** 原厂播放器或 NPE 实际产生正确音频，并能控制、停止和释放资源；
   检查对另一原厂声音用途的适用性，再按 M2 的范围补齐，而不是一段声音响了就结案。

当前未知算法和状态仍需要新证据。只排除一种解释属于逆向进展，不等于新增声音能力。
没有新证据时不重复搜索相同材料或盲填算法；明确记下所缺依据，转向已有依据、能实际实现的整机缺口。
其中 NPE 的正常技能取得、施法/装备或后续剧情仅用于定位尚未闭合的具体行为，
验证达到目的后即回到实现；不重复已通过的移动/战斗累积进度，也不把静音玩法进展计入 M2。
既有阿诺局部成果见[战斗与增量读回](../np560_npe_arno_battle.md)。

对尚未定位的显示、输入或运行故障写“原因待查”，不先假定 ROM 缺失。

## 6. 如何判定进展，而不是完成测试配额

每次实现任务只回答四件事：**缺什么能力、为何判断在这一层、实际改了什么、用户现在能做什么。**
逆向结论与功能完成分开汇报；新增证据很有价值，但确认一个入口不等于实现一个服务。

- 自动导航用于复现某个操作错误，画面比较用于定位/确认像素损坏，
  压力测试用于已怀疑的资源泄漏、累积状态或时序问题。
- 不设“自动导航平台”“画面校验平台”“千次压力测试”里程碑，
  不要求先完成工具建设或任意次数长测才开始功能实现。
- 复用现有诊断；只有当前缺陷确实无法观察时才补最小工具，之后立即回到实现。
- 修复需保留能区分前后的证据，做与改动风险相称的回归，并确认相应原厂使用流程。
  不取消必要验证，也不以按键 ACK、脚本退出成功、无报错或测试音替代实际功能。
- “完整”要求 A—H 的功能缺口消除，并在同一交付版本上工作；
  正常、边界、失败和恢复路径均应按所实现的设备语义处理。
- 不用脚本数、测试次数、逆向地址数、运行天数或无依据百分比表示完成度。
  始终报告新增能力、未解决问题和下一项实现，不把“尚未验证”写成“没有问题”。
- 测试保护用户实例与存档，采用隔离设备；端口号不代表版本，不因连接失败擅自重启。

### 最终交付门槛

- [ ] M1—M5 的真实用途均已实现；内容或外部服务缺失的项目明确列出，不能伪造成功。
- [ ] A—G 的已知硬件/ROM 缺口已解决，临时桩、按应用特判和开发者手动修补已清退。
- [ ] 原厂内容和真实 NPE 在同一套核心、ROM、前端与设备配置上工作，资料跨进程保留。
- [ ] 普通用户可以独立安装、操作、备份、恢复和更新；运行不依赖诊断工具。
- [ ] 未知或无法与真机核对的行为仍明确披露；未解决前不宣布“完美”或“与真机完全一致”。
