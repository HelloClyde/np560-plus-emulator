# NP560+ 完整、高保真模拟器实现计划

更新：2026-09-05，按用户“完美实现 NP560+ 模拟器”的要求重新规划。

本文是唯一有效的执行计划。旧版混合了大量实验日志与过时路线，已完整保存在
[历史计划](history/plan-2026-09-05-before-replan.md)，其中的顺序、勾选和“当前”不再作为执行指令。
详细逆向证据留在专题文档；本文件只维护目标、真实缺口、实现顺序与完成条件。
计划的计量单位是“实现了哪项真机能力”，不是脚本、截图、修补函数或测试次数。

执行主线：可靠的 CPU/SoC 与内存映射 → 补齐原厂执行路径需要的 resident ROM →
原厂系统正常操作 → NPE 完整游玩（含声音和存档）→ 全部应用、外设与整机忠实度收敛。
按实际依赖推进：游戏需要的声音、文件写入和定时中断必须提前实现，不拆成“游戏完成后的附加项”。
导航脚本、截图核对、压力计数不作为独立里程碑；也不等全部指令研究完才推进真实应用。

## 1. 最终目标，不以局部成功替代

实现能忠实运行原厂固件的 NP560+ QEMU 整机模拟器。最终效果应是可正常使用的虚拟真机，
不是菜单演示、单个游戏适配器，也不是由 Web 重写的一套学习机界面。

- CPU、存储器、总线、外设和时序共同支持原厂系统，不依赖按调用地址逐个“救活”程序。
- 开机有完整主菜单、开始菜单、时钟与状态图标；原厂应用可进入、正常操作并退出。
- 全部物理按键、短按、长按、组合键和释放行为正常，能在系统和游戏间连续使用。
- NPE 是核心交付目标：从 `开始 → 娱乐 → 游戏世界 → NPE 游戏` 选择真实文件并游玩，
  包括移动、动作、对话、场景切换、原游戏具有的声音和存档、读取存档、正常退出。
  《英雄传奇》是首个端到端样本，不是兼容性上限；继续覆盖其它真实 NPE 游戏。
- 音乐播放器能真正播放；原厂存在的其它声音、录音及媒体功能按实际硬件与固件实现。
- 文件、用户资料、设置和游戏存档可以持久保存；可以正常升级、关机、开机和恢复状态。
- 原机具有的其它应用和接口同样属于目标，不能因为主菜单/NPE 已跑通而排除。
- 用户能从明确来源的固件和自己的内容文件生成镜像、启动使用，无需手工修改 RAM/NAND。

“完美”是完整性和忠实度目标，不是提前作出的保证。目前没有真机、也没有完整原厂
mask-ROM 转储；无法确认的原厂行为、周期参数和 ROM 内容必须保持为待解决项。
证据不足不能写成“与真机完全一致”，也不能通过改写完成标准把缺口排除。

## 2. 当前起点与真正缺口

| 领域 | 已有事实 | 尚未实现或未证明的部分 |
| --- | --- | --- |

| resident / mask ROM | 已重建部分 guest 代码，来源包括原厂函数、常量与有证据的行为重建 | 不是原厂完整 ROM；启动、调度、装载、文件和媒体服务仍有推断与缺口 |
| 系统镜像 | 从最小出厂 NAND 按原厂条件分支完整烧录约 44 MB 原包，数据/ECC 正确且零按键冷启动通过；原厂文件 API 导入与冷读回已通过真实 NPE | factory 仍为逆向 fixture；全部文件系统读写、完整 USB 内容传输与剩余初始化语义 |
| LCD / 主菜单 | 指定修复镜像的五分类往返显示正确；最新开发构建能冷启动到完整桌面 | 不能把不同构建的结果合并成当前版本全部通过；跨应用、局部重绘、时钟边界、睡眠唤醒仍待完成 |
| 输入 | Web 到真实矩阵、原厂扫描和事件消费已打通 | 多轮 held-level 操作曾多消费事件；长按/组合键及计时仍需正确实现 |
| NPE | 旧镜像已有局部操作与退出记录；新设备已由原厂文件 API 完整导入《英雄传奇》，冷读回一致；共享窗口构建另一路线已进入文件列表，选游戏后停在原厂 Timer2 等待 | 正常导航尚有间歇性故障；Timer2 和流处理 ROM 仍缺；完整玩法、音频、真实存档及其它游戏兼容性均未完成 |
| 音频 | 有原厂调用和候选资源的逆向记录 | 无可验收的 guest 音频输出；三处临时音频返回桩；音乐播放器仍不能播放 |
| 整机使用 | Web LCD、虚拟键盘、启动器与进程日志已存在 | 稳定生命周期、持久化默认策略、整机快照、统一生成启动和交付整理 |

以上是分项证据，不是一个已全部通过的统一发行版。当前开发基线使用 `firmware-vma03`、
原始 `NP560.PRG`、`np560-system-v380-vma03-resident-codec-holes-v1.bin` 与原厂文件 API
导入的 `np560-vendor-file-import-v3.nand`；`ROM_HLE=off`、`HLE_UI=off`，显式报告 ROM 缺口。
构建及镜像身份见 [Timer2 与位寻址](np560_timer2_and_bit_sfr_contract.md)。端口号不代表版本。

共享窗口构建的一次正常菜单路径在确认“游戏世界”后停于 `22:1840 / WORD=bcd3`，未进入文件列表，
见 [路线记录](../tmp/np560-sfr-psr-native-route-v1/route.json) 与
[失败现场](../tmp/np560-sfr-psr-native-route-v1/04-NPEList-failed.json)。异常内容已匹配原包谚语资源。
旧构建和同一新构建的另一路线均进入过文件列表，但输入消费和前史不同，仍不能归因于
SFR 修正或认定为缺少新指令；见 [代码写入与复现边界](np560_game_world_code_write.md)。
随后已修复独立确认的中断 PSR 帧编码错误并通过冷启动，不能据此宣称间歇性覆盖已修。
继续修正了 SOCR/F100 分离导致 DI 不屏蔽中断的错误，原厂冷启动再次通过；这是对真实
临界区语义的修复，但尚未直接捕获资源覆盖的首次写入，下一步核对正常导航和 Timer2 路径。
此前另一构建、不同导航前史曾进入
NPE 并停在 `02:ACD8`，见 [流后端记录](np560_resident_stream_backend.md)；该 ROM 缺口仍须修复，
但不再把它描述为最新构建的首个卡点。没有重新验证的旧成果一律保留适用范围。

## 3. 实现必须遵守的架构边界

1. QEMU 模拟硬件；菜单、文件系统、应用和游戏由原厂固件及重建的 guest ROM 执行。
   不在宿主拦截 SCALL 伪造成功，不让 Web 直接改选中项、游戏状态或显存内容。
2. code/data 映射、银行切换和装载必须来自 SoC 机制及原厂装载规则。
   优先修复通用地址/总线语义，不为每个失败 caller 追加特殊别名。
3. 缺失 resident 行为按调用约定、数据结构、状态变化与原厂实现证据重建。
   每一类入口区分“原厂代码”“有证据的重建”“临时桩”“未知”，不把函数数量当完成度。
4. NAND 控制器和 ECC 属于硬件；FTL、目录、分区、文件分配与磨损策略由 guest 软件执行。
   调试注入或离线制作目录只能作定位手段，不能替代最终的正常初始化/导入路径。
5. Web 只呈现 LCD/状态电极、传递物理输入、播放 guest 产生的声音并提供设备操作。
   不用宿主字体补画菜单，不自行配乐，不用限速按键掩盖 guest 重复消费。
6. 未知访问先记录和区分：有效指令尚未实现、错误取指、真实未建模寄存器、正常保留位。
   不把错误控制流当新指令，也不把所有未知读取静默填零；开放总线等行为须有依据。
7. 保留用户运行现场、输入固件和存档。实验用独立实例和输出，不能通过重置用户实例试错。
8. 重建 ROM 追求可观察行为等价，不伪称恢复了未知的原厂逐字节内容。每个临时替代必须
   有适用范围、证据和退出条件；原厂代码复用、有证据重建与尚未知部分分别记录。

## 4. 核心能力清单：缺什么，实现什么

以下均属于最终范围；“尚无触发样本”不是删除该项的理由。

| 模块 | 要实现的实际能力 |
| --- | --- |
| DMCU CPU | 全部有文档或原厂代码证据的指令、寻址、标志位、寄存器银行、栈、调用/返回、重复执行、自修改代码与异常处理；未知编码继续辨别，不凭空添加 |
| 内存和总线 | PRG/NOR、mask-ROM、SRAM、数据 RAM、代码写窗、银行/片选、字节序、奇偶地址和边界行为；用硬件规则取代不合理的逐地址补丁 |
| 中断和时间 | IRQ 屏蔽/优先级/入口/返回、定时器、RTC 与外设事件；游戏速度、连发和音频由一致的虚拟时间驱动，不能取决于诊断轮询频率 |
| resident ROM | 复位交接、初始化、模块装载/重定位、内存和对象生命周期、消息/调度、资源/字体/绘制、文件与媒体服务；补齐实际缺口并消除伪成功桩 |
| LCD | ST7529 命令、寻址、像素格式、扫描方向、灰度、裁剪/局部刷新、显示开关和状态电极；时钟刷新不叠字，跨应用不残留 |
| 键盘和 GPIO | 完整矩阵扫描、边沿、保持、释放、去抖/连发相关时序和组合键；原厂软件负责键值与菜单语义 |
| NAND / ECC | 页/OOB、擦写、状态/busy、DMA 数据边界、ECC 及错误行为；使原厂分区、FTL、文件系统和升级器自行正确工作 |
| 音频 / 媒体 | 查明原机实际音频通路、控制寄存器和数据格式，补全 guest 驱动/ROM 服务及相应设备；输出可听声音，支持音量、停止、退出和原厂具备的输入能力 |
| USB / 内容传输 | 原机 USB 控制器、loader、命令/数据传输、升级和文件交换；RAM 调试装载不是 USB 完成的证明 |
| 电源及其余外设 | 电池/ADC、外接电源、开关机、睡眠/唤醒与复位；按原厂资料/访问证据盘点其它接口、外接存储或协处理器，不按其它学习机猜硬件 |
| NPE 运行环境 | 文件格式、原厂 loader/runtime ABI、资源读取、游戏逻辑与显示/输入/计时/声音/存档；不得以合成 NWF 或单独重写的游戏替代 |
| 原厂应用 | 学习、辞典、网络、记事、系统和开始菜单下全部实际入口，含娱乐、时间、计算、翻译、资料与媒体等；完成实际操作而非只有首屏 |
| 持久化与恢复 | 正常 guest 文件写入跨关机保存，升级与异常中断的数据处理正确；整机快照包含 CPU/RAM/设备/定时器等，不能把 NAND 文件叫作整机状态 |
| Web 与交付 | LCD/按键/声音/设备操作、明确的运行身份和存档状态；可重复构建与一键启动，错误可解释，正常使用不依赖开发者手动干预 |

## 5. 按依赖推进的交付里程碑

各项均未整体完成。M1 的系统可靠性是当前重点；M2 为 M3 提供声音与存储依赖。
所有里程碑必须在明确的同一构建/配置上成立，不能从多个实验镜像各挑一项拼成“已完成”。

### M1：原厂系统可以正常使用，不止能显示桌面

- 修复正常进入游戏世界时的取指异常，查清代码/数据映射、装载、写入来源和受影响机制。
- 收敛 CPU 寻址、标志位、SFR 访问、栈和中断状态；实现定时器、ICR 及原厂安装的中断向量。
- 补齐系统依赖的 resident 初始化、装载、对象生命周期和消息调度，逐步淘汰无依据别名与返回桩。
- 完整矩阵按键可按下、保持、组合、释放；原厂程序决定连发和菜单含义。
- LCD 命令、寻址、灰度、扫描、局部重绘和状态电极正常，时钟不叠字、切换不破坏菜单。

完成条件：同一新设备可冷启动，操作五个一级菜单和开始菜单，进入/退出文件浏览器；
显示、输入、前后台切换与计时正确，不需要调试写 RAM、强制事件或重启救场。

### M2：内容、声音和保存具有真实底层支撑

- 在已有原厂烧录/文件 API 成果上补齐初始化、目录和文件读写、关闭提交、错误处理与持久化。
  不重复制造已通过的整包镜像；最小出厂 fixture 的未知语义仍须追清。
- 恢复 NPE/媒体实际调用的流状态、缓冲管理和输出算法；不能靠返回成功跳过未实现的 ROM。
- 实现有证据的音频控制、传输/解码与设备输出；替换音频返回桩，由 guest 产生声音后送到 Web。
  文件打开、音量、播放、停止和退出均走原厂程序；录音等其它媒体能力仍列入 M4。
- 让 NAND/文件提交可跨正常关机保存；区分游戏原生存档、整机快照和前端页面状态。

完成条件：真实 NPE/媒体文件能正常导入和读取；音乐播放器可听、可控；guest 写入的文件
在重启后仍正确。RAM 调试传输只可作为已声明的开发过渡，不能因此宣布 USB 已实现。

### M3：NPE 完整游玩——核心可用交付

- 从 `开始 → 娱乐 → 游戏世界 → NPE 游戏` 选择真实文件，原厂 loader/runtime 完成装载。
- 首先打通《英雄传奇》的移动、动作、对话、游戏菜单、场景切换、退出和再次进入。
- 同时完成游戏本来具有的声音和原生存档；关机重启后能读取进度继续游戏。
- 按引擎/资源/输入差异扩展其它真实 NPE，修共同 CPU/ROM/外设机制，不做单游戏特判。

完成条件：用户可以连续实际游玩，声音、速度、显示和操作合理，能保存、恢复与退出。
只有标题画面、文件读回或一个关卡可走动，均不能把此项勾为完成。

### M4：补齐全部原厂应用与外设

- 学习、辞典、网络、记事、系统及开始菜单的实际功能逐项完成操作链，不能只验证入口首屏。
- 补齐 USB 控制器及原厂 loader/传输协议，完成正常升级和文件交换，退出调试 RAM 传输依赖。
- 完成原厂具有的录音/其它媒体、RTC、电池/ADC、外接电源、开关机、睡眠/唤醒及已确认的其它接口。
- CPU 全部有证据指令、异常、内存/总线边界及外设时序继续收敛，覆盖没有被首个游戏触发的部分。
- 对缺少内容或远端停服的功能，分开记录设备侧实现与外部依赖；不伪造成功，不悄悄删除目标。

完成条件：能力清单中所有原厂应用和设备都有实现、实际使用证据或明确未解决项。
任何未解决项仍意味着整机目标未完成，不能用 NPE 可玩替代整个 NP560+。

### M5：整机忠实度与可长期使用的最终交付

- 收敛时钟、音画同步、中断竞争、组合输入、资源释放、ECC/坏块与掉电/异常中断行为。
- 完成整机状态保存/恢复：CPU、RAM、设备、未完成传输和定时器状态一致。
- 统一镜像生成、构建、启动和用户数据保存方式；正常使用不依赖开发者临时补丁或调试器。
- 清退最终路径的无依据桩、调用点特判和实验注入，补齐 ROM 来源/重建说明、使用说明及已知限制。
- 有真机、转储或新增原厂证据时做差异核对；尚无依据的精确周期/边界行为不宣称已还原。

完成条件：从原始固件和用户内容可建立、使用、升级、保存和恢复完整虚拟设备；
跨应用、跨游戏的兼容性与长期使用表现成立，仍未确认的忠实度边界公开可查。

## 6. 工具与验证：支撑实现，不另立项目

- 画面校验用于发现具体绘制/资源错误，导航脚本用于重复一次已知操作；两者不等于功能已实现。
- 压力测试用于功能正确后的时序、泄漏和稳定性检查。取消“千次”等任意数量门槛，不以次数报进度。
- 每次修复验证触发故障、受影响的底层机制和实际功能链；不以“诊断无报错”代替画面、声音或玩法正确。
- 现有工具能定位就直接修实现。只有缺少回答当前问题所必需的信息时才补最小诊断，不扩建泛化工具平台。
- 验证不能强写 guest 状态、换掉错误的期望画面或伪造 ROM 成功；正常按键问题不能用单扫描输入掩盖。
- 每轮汇报四件事：新增可用能力、仍失败的操作、已证实原因/尚待定位之处、下一项实现。
  状态只用“未实现 / 部分可用 / 使用链已通过 / 真机一致性待证”，不按函数数或用例数算百分比。

## 7. 当前实现队列：先解除眼前阻塞

1. **恢复正常游戏世界入口。** 对最新 `22:1840` 取指异常做相同输入的构建对照，找出
   代码首次偏离的写入/映射原因并修其通用机制；不要添加 `BCD3` 指令或在取指前恢复特定字节。
   完成标志是同一新设备用普通按键进入原厂文件列表，不是再完成一份观察器。
2. **补计时与中断硬件。** 完成专用设备的 SFR 一致性、Timer2 计数/重载、ICR 请求、
   向量派发和返回。原厂声音启停等待必须由真实模拟中断结束，不能提前放行或宿主 sleep。
   中断帧/RETI 已统一为原厂 PSR 格式，SOCR/F100 和 IE 屏蔽已修正；下一步仍是计数和
   派发，不把寄存器和屏蔽修正视为 IRQ 系统完成。
3. **补 NPE/媒体缺失服务并推进完整玩法。** 恢复 `02:ACD8` 和 `01:B6DE/B7AA/B816/B84E`
   的有证据契约及共同流状态；随后处理真实游戏输入、输出、声音和原生存档。
   未证明的服务不能仅凭参数命名成某个 codec/延时函数，旧版本的局部游玩不能代替新版本通过。

三项不是僵硬串行关卡：发现真实依赖即先修依赖；无新分歧就继续实现功能。
用户报告的花屏、无声、按键和存档问题直接落到上述能力项，不再另开泛化工具建设阶段。

## 8. 最终完成判据

- 上述 CPU/SoC/ROM、外设、原厂系统与应用能力已实现，行为有证据约束，不以无报错代替正确。
- 从原始固件与用户内容建立新设备，可正常启动、使用、升级、关机、重启和持久保存。
- NPE 的真实玩法、输入、原游戏声音和存档/恢复、退出正常，并有跨游戏兼容性证据。
- 音乐播放器及原厂具备的其它音频功能真实可用；主菜单、应用、状态图标和时钟显示正确。
- 完整设备可通过 Web 正常操作，运行速度与计时合理，不依赖调试器或手动修补。
- 没有未声明的伪成功、画面替代或单游戏特判；尚无依据/实现/外部条件的项目保留为未完成，
  不能据此宣布“完美”。不按已写代码行数、重建函数数量、通过测试数量给出完成百分比。

本计划重排优先级，不撤销已有成果，也不把目标缩小到最容易通过的子集。
