## 有声战斗的指令分布（2026-10-02）

在隔离 8961 从原厂菜单读取《天降风云 V1.3》第一槽、经游戏内设置打开音乐，

直方图；`/api/opcode-profile` 读取时暂停 CPU、读取一致快照并恢复运行。
默认实例不开启统计，也不暴露可读的直方图。统计以客机执行次数计，
**不是宿主耗时百分比**；统计模式本身有开销，不用于速度验收。

隔离 v2 的 20 秒战斗窗口累计 299,316,503 条指令，最高 opcode 为
`9A` 57,568,816（19.23%）、`68` 26,776,346（8.95%）、
`58` 26,667,237（8.91%）、`AC` 24,375,084（8.14%）。进一步在
隔离 v3 取完整指令字，10 秒战斗窗口累计 122,430,490 条：
`9A53` 21,583,127（17.63%），`6810` 10,189,214（8.32%），
`88F0` 6,211,119（5.07%），`5600` 5,517,179（4.51%），
`AC01` 5,191,714（4.24%）。`9A53` 是原厂 Timer2 等待使用的
`BIT[53]` 位分支；`6810` 写 DS0。高执行次数不等于能跳过等待或
省略总线副作用；下一步应区分这些指令的真正宿主成本、DS0 改变
引起的 TLB 刷新次数，以及必要的时钟/中断边界，然后才做等价快路径。

`4.227/4.327`、`4.275/4.751`，宿主负载波动较大，不据此声明

## 可用采样路径，不再仅依赖GDB停顿

`scripts/probe_np560_perf_samples.py` 只自行启动QEMU，没有任意PID附加入口。

线程comm全部被截为qemu-system-dmc，不能按CPU/TCG线程名选择。

- Linux x86_64限定，2ms CPU时钟采样周期，IP/TID记录，排除kernel/hypervisor。
- 1MiB有界环缓冲；先禁用事件再读静止缓冲，不边运行边读head/tail。
- 记录原始IP、进程映射、丢失记录及其他记录；当前没有调用栈或符号解析。
- 这是有开销的采样，不是速度基准。没有lost记录不等于所有环境都无丢样，
  长窗口仍须检查容量/丢失情况，不用样本数推算实际执行时间。
