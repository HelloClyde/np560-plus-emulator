## 新服务的明确边界

v3 重建 session 每个 granule 用两组软件循环复制 2×576 个 PCM16，
每样本 4 条 guest 指令，仅循环体便有 4608 条。v4 仅将这段**我们重建的软件复制**
改为已登记 HLE，减少宿主执行负担；不是硬件 DMA 加速或替换原厂处理函数。

- 输入 `DS0:R3`：已由 native session 取得 BUSY 的 owner；`R0`：下一相位 0/1。
- 验证 owner 的地址/签名/句柄、MAGIC、BUSY 和旧 PHASE；验证工作区大小与
  已登记的解码 session、工作区 MAGIC、有效 PCM 数为 576。
- 验证四个输出均为 X0 中偶地址、1152 字节范围有效且互不重叠。
  **所有地址验证完成才写输出**，错误返回 R0=0/R2=2，缓冲不变。
- 正常复制左右各 1152 字节到该相位的输出缓冲，返回 R0=576/R2=0。
  不改变 owner 的 PHASE、READY、STATUS 或源 PCM；除结果寄存器外保持调用环境。
- 之后仍由原 native session 发布 PHASE/READY，执行原厂格式/输出回调，
  原厂配置双缓冲，再逐请求经过实际 DTU → DAC → PCM → Web。

构建显式要求 `--hle-free-words --deferred-input-retirement --hle-pcm-copy`。
v4 有 6 个版本化门；旧 v1/v2/v3 构建的 ROM SHA256 均与原产物逐字节相同。
不能将 v4 门地址与 v3 混用：本构建 base=138790 (`02:1E26`)，copy=`02:1E76`。
