# F010：清退误建的键盘 GPIO，恢复原厂音频软件状态

日期：2026-09-06。已实现并通过定向原厂函数验证；不代表声音 ROM 已恢复。

## 原厂证据推翻旧解释

旧模型将 `F010` 的 unbanked 视图覆盖为键盘外设，读取返回 `4 | 方向键掩码`，
写入只计数、不保存。banked 视图和 `BIT[88]` 却使用真正 RAM，导致同一地址有两种状态。
此前把 `4` 解释为存储单元、把 `31:D9AA` 命名为五键 GPIO 扫描器，证据不足且实际错误。

本次核对原始 V3.80 PRG，运行地址采用 VMA03（文件偏移为运行地址减 `030000`）：

| 原厂函数/位置 | 实际操作 |
| --- | --- |
| `08:3292`，其中 `08:32B6..32BC` | 选择 DS0=1，向 logical 7010，即 physical F010 写入 4 |
| `08:2F22`，其中 `08:2F40..2F48` | 把首参数的高 12 位写入同一 F010 |
| `08:315C..315E` | 设置 BIT88.1，清 BIT88.2，更新该软件状态 |
| `08:31AC/320E/3238/3262` | 启动、继续、暂停、停止路径读取并修改 BIT88.0/.1/.2 等位 |
| `31:D9AA..DA40` | 以 IGNDS 读取 F010 的 10/20/40/80/800 掩码，更新 51:2A76 的 bit 0 |

因此 `31:D9AA` 至少是上述软件状态的消费者，不是方向键 GPIO 的依据。
不把其每个高位的精确业务含义进一步猜成某种已知 codec。

已用 PDF 技能渲染并查看 [CN1916884A 原件](../tmp/cnpatent/CN1916884A.pdf)
第 128 页图 2：`00:F000..00:F0FF` 为 128 words、可按位访问的双端口 SRAM，
SFR 从 `F100` 开始。第 129 页图 4 的 DS/15-bit 地址拼接与原厂 7010 写入对应。
这里以架构资料和原厂生产者/消费者交叉确认，没有只凭地址名称删除设备。

## 修复

- 删除 `np560.c` 中 F010 键盘 MMIO 的映射、合成输入、忽略写入的回调及其专用计数器。
- 普通数据、banked、内部和 BIT88 路径现在自然指向同一 SRAM backing；未新增复制状态或地址特判。
- 物理输入继续通过 F160/F164 矩阵；Web 没有修改 guest 音频状态、菜单或选中项。
- 只读状态以 `DPRAM_F010` 显示实际 RAM 值，不再显示虚构的 `KEY_GPIO/F010_READS`。
- 旧启动验证改用已有 `31:D9AA` 调用记录作为 dispatcher 证据，不再依赖被删 MMIO 的读取次数。
- 旧 ROM builder 的符号名暂保留以避免无关重命名，但状态说明纠正为软件音频状态扫描器。
  原厂 PRG、实际重建 ROM 二进制、NAND 均未更改。

## 原厂反例与修复结果

`scripts/tests/test_np560_audio_state_ram.py` 调用完整原字节 `08:3292`、`08:2F22`、
`24:9BD4` 和 `31:D9AA`；执行前逐字节验证实际 code bus 中的函数。
外围是诊断 caller，四个回调/缓冲均传空、rate=0，明确只验证状态设置，不冒充解码和播放。
Host 只控制开始/停止、物理输入和读结果，无 RAM 写入，无 NAND。

有效旧版反例：`tmp/np560-audio-state-before-20260906-v3/report.json`。
修复后：`tmp/np560-audio-state-20260906-v1/report.json`，上述场景普通及 icount=5 均通过，
所有 caller 正常返回、SP=6000、已监控 CPU/ROM 故障为 none，自有 QEMU 均 exit 0。

前两次夹具错误保留在 before-v1/v2：最初没有提供现有 code alias 需要的 NOR source，
随后误以为向 runtime RAM 写入能更新该 code alias。它们没有执行完整待测流程，不能当
F010 缺陷验证。v3 保留完整 NOR 来源并先核对 code bus；没有为修测试改变该旧映射。

额外的 F010 字/字节/位/FP 内部视图检查通过；直接高 SFR88 仍独立。首次测试误把
`1F88` 当 PUSH REG88（实际为 POP REG08），仅修为直接 CMP 后通过，未改 CPU 满足错误预期。
原有低 SFR、PSR、跨银行进位与原厂 Timer2 等待均重新通过。

`tmp/np560-audio-state-dac-20260906-v1/`：诊断 DAC 数据、原厂 08:33FA 渐变、普通/icount
输出及活动中复位通过。它仍不是游戏资源的声音，不以该 WAV 替代原厂解码验收。
