# REP / REPB 独立状态与 NPE 背景滚动修复

日期：2026-09-06。修复对象是 QEMU DMCU CPU，不是新 ROM 服务或 Web 绘图补丁。

同日后续：[REP 非法目标边界](np560_repeat_legality.md) 已阻止禁用目标产生副作用，
但 IREP 的 EXR/向量派发仍未实现。本文原始滚屏实验的核心与结论保持不变。

## 实际故障

从《阿诺创世纪》原生第一槽恢复地图 3、世界 `(1,25)`，向右点按十次后到达 `(11,25)`，
视口偏移由 `(0,21)` 变成 `(4,21)`。原厂视口 tile 数组 `52:70B4` 的 105 个 word
全部与游戏原始地图一致，但 LCD 栅栏仍停在原来的横坐标，背景只有局部更新。

前后绘图缓冲都已包含相同错误，因此不是 Web 没刷新或 LCD 单独漏写。
这是长期残留，非一次采样抓到滚动中间帧。

原始地图数据依据：阿诺文件 `0x10C969` 起的 32×29 个 big-endian tile word，
原视口第一行位于 `0x10CEA9`；按偏移取出的七行与实际 RAM 逐项对应。
这些读取只用于定位与选择物理按键路线，没有写回游戏坐标或碰撞结果。

## 根因与依据

本地 `tmp/cnpatent/CN1916884A.pdf` 的 PDF 第 120 页和第 122 页已整页渲染、目视核对：

- `REP` 使用 SRC 重复下一条指令；执行次数为操作数加一。
- `REPB` 使用独立的 RC、RS、RE 重复一个指令块。
- 单指令重复目标不能是 REP/REPB 等禁止指令；这与 REPB 块中出现合法 REP 不是同一种嵌套。

原厂 `0D:78D2`（PRG source `2A:78D2`）的方向 0、2、3，明确使用外层 REPB 遍历各行，
内层 REP 搬移一行的字节；方向 1 使用显式行循环和块内字节循环。
该函数早已恢复，函数体与原厂字节相同，不缺 ROM。

旧 CPU 把两种指令都写入 `repeat_pc/end/count/block`。
进入内层 REP 后外层循环被覆盖，因此方向 0 只搬移第一行，随后调用者继续画新边缘和角色，
形成“地图数据正确、背景拼接错乱”。原厂四方向代码不需要修改。

## 实现

- `target/dmcu/cpu.h`：新增单指令 `single_repeat_pc/count`，与原块循环字段分开。
- `target/dmcu/helper.c`：REP 只设置 SRC 状态；单指令重复结束后才判断外层块末尾。
  即使 REP 的目标恰是块内最后一条，也不会提前消耗外层次数。
- `target/dmcu/cpu.c` 与 RETI：中断同时保存、清除和恢复两套循环状态；嵌套中断的影子包含两者。
  CPU 复位沿现有完整清零路径清除新增状态。
- `hw/dmcu/np560.c`：现有 `IRQ_REPEAT` 只读信息追加 SRC 与 SAVED_SRC，避免将单指令状态隐藏。

未增加无限循环栈或按游戏/PC 生效的模拟逻辑；保留一套单指令和一套块循环状态。
未改原厂 PRG、重建 ROM、NPE、LCD 或 Web。

使用同一 PRG、ROM、NAND，在新核心冷启动，从原厂游戏列表进入阿诺“再续前缘”第一槽。
没有修改运行中 RAM，没有关闭本轮新出现的错误来强行继续。

  旧核心有 1,421 像素错误，新核心为 0。

  最后一次方向 helper 返回 2；本轮未进一步追踪该处交互判定，不把未前进直接归为漏键。
  背景向下移动 64 像素；比较新画面 `y=68..115` 与旧画面 `y=4..51`，
  排除当前角色矩形 `x=108..131,y=60..87` 后，11,040 个背景像素差异为 0。
  当前视口 tile 与原文件仍是 105/105 对应。
- 实际流程未出现 ROM_MISSING、INVALID_CONTROL 或 UNSUPPORTED。
